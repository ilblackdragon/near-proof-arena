## 2. Implemented behaviour

### 2.1 `NearSpecV3/AltBn128.lean` (859 lines after the theorem addition)

Field and curve layer, all **little-endian** per nearcore's wire format (`decode_u256` splits each
32-byte word into `lo ‖ hi` `u128`s and reads each `from_le_bytes`,
`runtime/near-vm-runner/src/logic/alt_bn128.rs:143-149`):

* `Fq` — the 254-bit prime
  `q = 21888242871839275222246405745257275088696311157297823662689037894645226208583`;
  `add`/`sub`/`mul`/`neg` as `Nat` modulo `q`, `pow` by square-and-multiply, `inv` by Fermat
  (`a^(q−2)`), `inv?` returning `Option`.
* `G1: y² = x³ + 3` in Jacobian coordinates — `dbl` (`groups/mod.rs:378-404`, `a = 0`), `add`
  (`add-2007-bl`, `groups/mod.rs:493-540`), `neg`, 256-bit MSB-first `smul`, `affine?` via `Z⁻¹`,
  and `subgroupCheck = true` (`groups/mod.rs:576-578`: `#E(Fq) = r`, so on-curve implies
  in-subgroup).
* `Fq2 = Fq[i]/(i²+1)` (`beta = q−1 = −1`), with `mul`/`sqr`/`inv` (norm) and `ξ = 9+i`;
  `Fq6 = Fq2[v]/(v³−ξ)`, `Fq12 = Fq6[w]/(w²−v)` matching `zeropool-bn-0.5.11`.
* `G2` on the twist `y² = x³ + 3/(9+i)`, with a **real** subgroup gate `[r]P = O`
  (`groups/mod.rs:120-122`, `:672-674`), unlike G1's constant `true`.
* The Miller loop and final exponentiation for the **reduced Tate** pairing, plus `productIsOne`.
* The codec: `decodeFq` (rejects `≥ q`), `decodeFr` (rejects `≥ r`), `decodeG1` (`(0,0)` = infinity,
  else on-curve), `decodeFq2` (real first), `decodeG2` (twist + subgroup), `decodeBool` (`0`/`1`),
  `encodeG1` (infinity = 64 zero bytes), and `chunksExact` mirroring `stdx::as_chunks_exact`.
* The three payloads `g1MultiExp`, `g1Sum`, `pairingCheck`.

### 2.2 The three host arms in `NearSpecV3/Wasm/CryptoHost.lean`

Each arm is additive: `cryptoHostCall` gains a `| "alt_bn128_…" => some do …` line; `hostCall`
(the D3α table) is untouched.

* `hostAltBn128G1Multiexp` / `hostAltBn128G1Sum` — the shared `altBn128Writer`: `payBase`, **read**
  (`memOrRegH`), split-length gate, `payPer`, decode, register write. A non-multiple length is an
  error *before* any per-element charge.
* `hostAltBn128PairingCheck` — `payBase`, read, split gate, `payPer`, decode, and the `0`/`1`
  verdict pushed as a `u64` with no register write.

### 2.3 Pinned semantics transcribed

|---|---|---|

| charge order | `logic.rs:939-949` | base → read memory/register → split → per-element → payload |

### 2.5 Pairing choice (and its exact residual risk)

`bn` computes the **optimal ate** pairing. This module computes the **reduced Tate** pairing. That is
sound for these hosts because the host only asks whether `∏ e(g1ᵢ, g2ᵢ) = 1`: any two non-degenerate
bilinear pairings into `μ_r` differ by a single exponent `c` coprime to `r`, so `∏ t = 1 ⟺ ∏ e = 1`.
**This is an argument, not a proof**, and it is tested against the pinned oracle on all 56 directed
and 3,120 generated rows rather than proved. It is recorded here as a residual premise, not a
theorem.

## 3. Theorem statements and residual premises

All in `NearSpecV3.AltBn128`; `#print axioms` output in
`evidence/lean-chunk-L3-bn128/axiom-audit.out`.

### 3.1 Field-operation laws (unconditional)

| theorem | statement |
|---|---|
| `Fq.add_mod` | `Fq.add a b % q = (a + b) % q` |
| `Fq.mul_mod` | `Fq.mul a b % q = (a * b) % q` |
| `Fq.sub_mod` | `Fq.sub a b % q = (a + q - b % q) % q` |
| `Fq.neg_mod` | `Fq.neg a % q = (q - a % q) % q` |
| `Fq.add_lt` … `neg_lt` | every operation returns `< q` (canonicity) |
| `Fq.q_pos` | `0 < q` |
| `Fq.cast_add` / `cast_mul` / `cast_sub` | the `Nat`→`Int` bridge: the `Nat` result casts to the plain `Int` operation modulo `q` |

`cast_sub` is the only non-definitional one: since `b % q < q ≤ a + q`, the truncating `Nat`
subtraction never truncates, and `omega` closes it.

### 3.2 Curve membership preserved by the group law (unconditional in the *defect* form)

| theorem | statement | residual premise |
|---|---|---|
| `dbl_defect_int` | the Jacobian doubling output's defect `Y₃² − (X₃³ + 3Z₃⁶)` equals `64·Y⁶` times the input defect | none |
| `add_defect_int` | the Jacobian addition output's defect is an explicit combination of the two input defects | none |
| `dbl_membership_int` | affine doubling: `y² = x³ + 3 ∧ 2yλ = 3x² ⟹ y₃² = x₃³ + 3` | `λ` is the tangent slope |
| `add_membership_scaled` | affine addition, denominator-free: `(x₂−x₁)²·(y₃² − (x₃³+3)) = 0` | `λ(x₂−x₁) = y₂−y₁` |

The two defect theorems are the strong statements: an on-curve input gives an on-curve output with
no slope hypothesis at all. The two affine theorems carry the slope relation as an explicit
hypothesis because the executable code obtains `λ` through `Fq.inv`; stating the divided quantity
directly would require an inverse witness. For distinct field points `(x₂−x₁)² ≠ 0`, so the scaled
form is equivalent to the usual statement.

### 3.3 Pairing verdict structure

| theorem | statement |
|---|---|
| `productIsOne_nil` | `productIsOne [] = true` — the empty product is one, so an empty `pairing_check` input is the `1` verdict |
| `chunksExact_nil` | `chunksExact n [] = []` |

### 3.4 Axiom audit

Every one of the 18 declarations in the changed closure depends only on
`[propext]`, `[propext, Quot.sound]`, or `[propext, Classical.choice, Quot.sound]`. `Fq.q_pos` and
`G2.inSubgroup` depend on nothing. **No `sorryAx`, no new axiom, no `native_decide`, no
`implemented_by`.** `grep -c sorry` over the four changed Lean files returns 0 code occurrences (the
single textual hit is the prose "no `sorryAx`" in the module docstring).

### 3.5 What is *not* proved

* That `Fq` is a field (primality of `q`), so `Fq.inv` is not shown to be a true inverse; `inv?`
  returning `none` is the only guard. Group-law theorems are stated over `Int`, so they do not
  depend on this.
* That the group law computes the chord–tangent group operation on `E(Fq)` (closure and the defect
  identities are proved; associativity, identity and inverse laws are not).
* That the reduced Tate pairing agrees with `bn`'s optimal ate pairing — tested on every vector, not
  proved.
* That any whole chunk reaches these hosts (`cryptoHostCall` has no caller).

## 5. Failures found and how they were resolved

1. **The module docstring claimed curve-membership theorems that did not exist.** The Status
   section asserted "curve membership preserved by G1 doubling and addition and by G2 doubling and
   addition", but `grep -n theorem NearSpecV3/AltBn128.lean` returned only the `Fq` laws and
   `productIsOne_nil`. Fixed by actually proving the four identities (`18592e7d9`) and rewriting the
   Status section to list exactly what is proved and to name the residual premise. This is the one
   substantive correctness fix in this substream's later work.
2. **The affine addition identity defeated `grind` at its default limits** (`maximum number of ring
   steps reached`, threshold 100,000). The scaled form (`(x₂−x₁)²·defect = 0`) is a much smaller
   polynomial and closes with `grind (splits := 100) (ringSteps := 2000000)`. The Jacobian
   identities need `(splits := 200) (ringSteps := 4000000)` for addition.
3. **The inventory generator did not see the alt_bn128 arms as curve arms.** It read
   `Wasm/CryptoHost.lean`'s `cryptoHostCall` table but the rows were hard-coded `missing` by the
   `name.startswith(CURVE_PREFIXES)` fallback before the `crypto_arms` branch. The arms *are* in that
   table, so the `crypto_arms` branch applies; extending the scan's docstring to say so and
   regenerating moved exactly the three rows `missing → partial`.
4. **An apparent `EXIT=1` from the payload test was a measurement artefact.** The first run was
   wrapped in a shell `timeout` that fired at 120 s while the binary needs ~3 m 50 s; the binary
   itself printed `3176/3176 ok, 0 failures` and, run with a sufficient timeout and explicit
   redirection, returned `EXIT=0`. `TestAltBn128.main` returns `1` only when a comparison fails.

## 6. Infeasibilities and what is deliberately not claimed

* **Whole-chunk reachability is not established and was not attempted here.** `cryptoHostCall` has
  no caller; wiring the successor dispatch is the integration lane's file
  (`Wasm/Host.lean`, `Wasm/Exec.lean`, `D3/FunctionCall.lean` are shared/owned elsewhere). Adding
  the arm to `cryptoHostCall` only, as instructed, is what was done. **Adapter patch needed:** route
  `Exec.callHost`'s curve-host branch to `cryptoHostCall` instead of reporting `unmodeled`, then a
  whole chunk can reach these three arms. Until that lands, criterion 1 is unmet and `partial` is the
  correct status.
* **The reduced-Tate-vs-optimal-ate equivalence is not proved**, only argued and tested. A full
  proof would require formalising the ate pairing and its relation to the Tate pairing.
* **`Fq` primality and field axioms are not proved.** `inv` correctness therefore rests on the
  tested behaviour of the arithmetic, not on a theorem.
* **No `#guard`-style kernel-checked vector table was added**; the vectors are checked by the
  executable `nearspec-v3-test-altbn128`, which the acceptance contract permits (a new Lean
  executable). The generated corpus is 1,040 comparisons per host across four seeds, meeting the
  "≥ 1,000 per family across ≥ 4 seeds" bar per host.
* **CI does not run these executables.** `.github/workflows/ci.yml` builds with `test: "false"`, so
  the test binaries are compiled but not executed. That is a W01 harness gap, recorded rather than
  papered over.
