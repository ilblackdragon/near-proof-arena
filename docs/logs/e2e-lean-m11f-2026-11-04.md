## 1. `StViewE` for lane B (item 1)

**Key list in `StV`.** `StV.eng` keeps its arity (lane B pattern-matches `.eng p st`) but its
second field is now `EngSt := {st : Recording, keys : List Bytes}`. The key list is a function of
the intake: `ViewImpl` has a new field `keys : Intake → List Bytes` and `split κ` puts
`stOfK (κ I) c` in the state component (both `eng` and `call`); `unsplit` drops it, so
`split_inj` holds for every `κ`. `keysOf (stOfK K c) = K` (`keysOf_stOfK`, `rfl`).

* The honest `κ I` is the chunk's touched keys in the circuit's leaf order (sorted, as INTAKE's
  `WSB` rows enforce). Binding needs nothing about `κ`; completeness/segment soundness need it to
  cover every committed key (`OvlFacts.covered`).
* **Compatibility.** `stOf c := stOfK [] c` is kept because lane B's `FitsReach` names it. That
  definition now has the empty key list, so lane B's `FitsReach` should move to the `stOfK` form
  (`FitsReachK` in the join file). Shown concretely: `fitsB stViewE (stOf demoConf) = false` and
  `fitsB stViewE (stOfK [[1, 2]] demoConf) = true` (kernel `decide`).

**`encE_inj`.** `StEnc.lean`: a `Ser` class (encoder + prefix-freeness) with instances for `Nat`
(LEB128), `UInt8`, `Bool`, `Unit`, `Char`, `String`, `ByteArray`, pairs, `Option`, `List`, `Sum`,
`Std.TreeMap` (the tree itself: maps with equal contents but different balancing are different
values, so the shape is encoded; the WF proof is irrelevant), `PTrie`/`Kids` (mutual), and the 43
spec types of `StV`'s closure (found by a meta-script; structures via field tuples, inductives via
nested sums, injectivity by `cases`). `encStV_inj : encStV a = encStV b → a = b` for **all** `StV`,
so lane B's `encE_inj` (on stripped components) holds with no hypothesis on `strip`.

**`idxOf`, `depth`.** `depth = 24` (`IX_BYTES = 3`). `idxOf = 0`: the change index is the state
lane's offline-memory timestamp inside a segment; a boundary binds the working set by its root
(`RCH`), so timestamps can restart per segment. A running counter across boundaries is not a
function of the configuration and would have to be carried in `EngSt` like the key list. **Lane B
to confirm** that its AIR can rebase the index at a cut; otherwise this field changes.

**Instance** (`join/StViewE.lean`, lane E's file outside lane B's dir): `stViewE : StViewE`, so
`stD_binding_E : Coll (stD (stViewParams_B stViewE)) → Sha384Coll ∨ Sha256Coll ∨ LeafColl` and
the `hst` premise of `viewImpl_binding_bad` (`viewImpl_hst_E`) have no open field.

**`FitsReach`.** `fitsReachK_of` reduces `FitsReachK κ R` to `EngOvlInv κ R`: every reached
overlay satisfies `OvlFacts (κ I) o` (≤ 2^24 keys, every key's pre/current value < 2^24 bytes,
`o.trie.wf`, committed keys distinct and in `κ I`). `fitsB_none` covers components without an
overlay. **Open:** `EngOvlInv` itself, a pass over the engine's overlay operations (`Ovl.set`,
`remove`, `commit`, `rollback`, the logged mirrors): trie never modified after `Ovl.ofTrie`,
`kvPut` keeps keys distinct, value bounds. Not attempted.

## 2. NvAir exporter and `NodeTape` (item 2)

**Exporter** (sub-agent; reviewed). Deps: `setup_e2e_verify_deps.sh` with `E2E_ZK=1
E2E_TREE=1` into `/data/illia/nearproof-deps/laneE-nv/` (target 504 MB, kept). `nv_export.rs`
keygens `NvCircuit::new(3, 17, 1)`; the `program_part` variants (wrap: one 76-column part; tree
leaves/nodes: 72 + 4 cached) give the same DAG after re-keying columns (sha256
`1946c796…d032b6`, checked by the exporter). Output `NvAirExport.lean`: 79,822 B, 4,518 nodes,
548 constraints, 49 interactions, 19 public values, max degree 9.

* `setup_e2e_verify_deps.sh` is not re-runnable on a finished tree (its cpu-fast step regenerates
  that patch from a backend the e2e patches have changed). `setup.sh` re-checks only the
  reverse-apply of the five e2e patches on a finished tree. Latent bug in the shared script; not
  fixed (lane D's).

**Buses** (from keygen): NvAir uses 0 slot, 1 job, 2 digest, 3 mem, 4 bind, 5 acc, 9 sha_iface,
11 byte, 12 tr_sample, 14 tr_chain, 15 chain_start. Only 9 (Sha512Air4) and 11 (ByteAir) are
shared; Sha512Air4's 6/7 need TableAir4. **Vacuity guard** (`nv_closure`, `decide`): the closure
of NvAir under bus sharing is exactly {NvAir, Sha512Air4, TableAir4, ByteAir}, `NvPinned`'s four
tables. Bus 3 (mem) is NvAir's alone (`mem_users`), so its global balance is NvAir's own
(`memBalance_of_global`).

**Semantic finding.** NvAir's interactions have **field-valued counts merged across roles**
(mem slot 0: count `−ka·mult + kb`, message `ka·(y, c) + kb·(ya, e1a)`). `ZkFormal.Air.Interaction`
(bit-decomposed natural multiplicities with a send flag) cannot express this, so
`HoldsLogUp Pin.air` over a `ZkFormal.Air` transcription is **not** the circuit's predicate.
`NvTape.lean` uses the backend's semantics: `NvConstr` (every exported constraint, as
`ZkFormal.Air.Expr` via `dag`) and `MemBalance` (per message, counts sum to 0 in `Fp`).
`NodeExec` should be restated over this semantics when the other components are modelled.

**`NvTape.lean`** (standard axioms):
* every expression used is identified with its exported node by `decide` (`dag_*`);
* `flags`, `pad_next` (stage polynomial), `role_prefix`, **`y_row`** (y = row index on role rows);
* `alu_onehot` (selector halves one-hot on ALU rows: 256 + 32 boolean cases), `sel_bool`;
* **`mem_slots`**: every mem entry is an ALU key `(y_r, c_r)` or has count 0/1;
* **`hit`**: field LogUp with < p entries ⇒ a count-1 read is matched by a key;
* **`pvd_read`/`pvd_cells`**: a `PvD` row reading `addr` sees row `addr`'s `c`, which therefore
  equals `pv[1..13]` (lo) / `pv[13..19]`, `0` above limb 6 (hi);
* **`nodeTape_of_pvd`**: `E2ENode.NodeTape (dec ∘ pvDigest) R pub` when `R.outDig = dec
  (digCells …)`.
* Premises left: `PvdAt` (program binding + op decode via the byte bus), the LogUp balance as the
  extractor's output (mod `gkrBad`), height ≤ 2^24.
* Non-vacuity: `zero_holds` (the all-zero trace satisfies `NvConstr ∧ MemBalance`, all 548
  constraints by kernel evaluation). `PvdAt` needs an honest NV trace: not exercised.
