## 2. Implemented behaviour

### 2.1 `NearSpecV3/BLS12381.lean` (1,145 lines)

Field and curve layer, all big-endian per nearcore's wire format:

* `Fp` — the 381-bit prime, canonical `< p` decode via a `bendian_from_fp` round-trip equivalent
  (`read_fp_point`, `logic/bls12381.rs:386-404`), `sqrt` via `a^((p+1)/4)` (`p % 4 = 3`,
  kernel-checked as `p_mod_four`), big-endian encode.
* `Fp2 = Fp[u]/(u²+1)` — **`c1 ‖ c0` order**, not EIP-2537's `c0 ‖ c1`
  (`read_fp2_point`, `logic/bls12381.rs:406-436`).
* `G1: y² = x³ + 4`, `G2: y² = x³ + 4(u+1)`, affine + Jacobian, subgroup tests via 255-bit scalar
  multiplication, compressed/uncompressed codecs, SSWU maps, and the eight register payloads.

### 2.2 `NearSpecV3/BLS12381Pairing.lean` (520 lines)

`Fp6 = Fp2[v]/(v³ − (u+1))`, `Fp12 = Fp6[w]/(w² − v)`, the optimal-ate Miller loop, final
exponentiation, and the three-way `pairingCheck` verdict (`0` product one, `1` malformed/not in
subgroup, `2` product ≠ one) with no register write
(`logic/bls12381.rs:329-384`, `wasmtime_runner/logic.rs:1352-1376`).

### 2.3 `NearSpecV3/Wasm/CryptoHost.lean` (261 lines)

Nine host arms plus the `cryptoHostCall` dispatch table. The charge orders, transcribed and
re-read side by side in **both** runtime copies (`wasmtime_runner/logic.rs` and `logic/logic.rs`,
which agree):

* eight `bls12381_impl!` writers — `pay_base`, `pay_per(element, len / ITEM_SIZE)` where `len` is
  the **operand** `value_len`, **then** read, then decode. A length that is not a multiple still
  pays base and `⌊len/ITEM_SIZE⌋` elements, then raises `BLS12381InvalidInput` from
  `check_input_size` (`logic/bls12381.rs:438-452`).
* `pairing_check` — `pay_base`, **then read**, then `pay_per(pairing_element, data.len() / 288)`
  computed from the **read data**, then decode. An out-of-bounds read therefore burns base + the
  read cost and no per-element charge.

Return split: success → `0` + register write; decode/curve/subgroup failure → `1`, no write.
Register-sourced input (`value_len = u64::MAX`) overflows the per-element multiplication and
raises `HostError(IntegerOverflow)` after paying only the base — reproduced explicitly.

Gas: all 18 constants match PV86 `parameters.snap:184-201` exactly. `bls12381_not_in_group_fix`
is `false` at PV86 (`parameters.snap:289`), so every decode runs at `version = 0`.

19 theorems, all axiom-free within `{propext, Classical.choice, Quot.sound}`; no `sorry`/`sorryAx`
and no `native_decide` in any BLS module. Verified with `#print axioms` on each.

| `BLS12381.pairingCheck_nil_decode` | empty decode → the `if productIsOne [] …` form | propext, Quot.sound |

**Residual premises, stated honestly.** These theorems are *structural*: they pin the empty-input
case and the field constants, not the curve arithmetic. There is **no** theorem that
`p1Sum`/`pairingCheck` agree with `blst`; that obligation rests entirely on the 9,454 differential
comparisons against the oracle binary. `productIsOne_nil` deliberately leaves `finalExp one = one`
unreduced (a 381-bit final exponentiation exhausts the elaborator's recursion budget), so the
numeric half is checked by the compiled suite, not the kernel. `G1.inG1`/`G2.inG2` likewise need
255 scalar doublings and are tested against the oracle rather than kernel-reduced.

## 5. Failures found and how they were resolved

1. **Stale binary gave a false 4-failure reading.** The first host-suite run reported
   `135 total, 4 failures` with the four `pairing: register N bytes …` strings. The binary
   (`04:58:09`) predated the restored `CryptoHost.lean` (`04:58:22`), so it still carried the
   deliberately broken charge order from the earlier controlled-breakage experiment. After
   `lake build nearspec-v3-test-bls12381-host` the same suite reported `135 total, 0 failures`.
   **Lesson: the binary timestamp must be ≥ the source timestamp.** This run's numbers are all
   post-rebuild.
2. **Citations were wrong.** The BLS sources cited `logic.rs` without saying which of the two
   runtime copies, and several ranges were off: `bls12381_impl!` was cited `33-105` (should be
   `33-83`; `105` is inside `bls12381_p2_sum`'s doc comment), `check_input_size` `438-450`
   (should be `438-452`), and the blst ranges pointed into a different blst revision. All are
   corrected and machine-checked.
3. **The oracle and fixtures were untracked.** `oracle/bls-oracle/`, `gen_bls_fixtures.py`,
   both fixture corpora and the 94/94 claim were all uncommitted, so nothing was reproducible from
   the branch. Now committed, and both generators reproduce byte-identically.
4. **Dispatch was untested.** The 135 host cases called `hostP1Sum` etc. directly; no case
   consulted `cryptoHostCall`, so deleting an arm would have gone unnoticed. 12 dispatch checks
   added; controlled breakage (removing the `p2_decompress` arm) now yields exactly one failure
   and exit 1.
5. **The `exit 0 on failure` suspicion was a measurement artefact.** An earlier run piped through
   `tail`, so `$?` was `tail`'s status. `TestBLS12381Host.main` does return `1` when `bad > 0`;
   the stale-binary run proved it (`EXIT:1` with 4 failures). Captured with explicit redirection
   here.

## 6. Infeasibilities and what is deliberately not claimed

* **Acceptance criterion 1 is unmet.** "At least one real chunk in each supported entry path" is
  not satisfied and cannot be satisfied additively. `cryptoHostCall` is defined but never called;
  `D3/CryptoDomain.lean` documents why wiring it into `Wasm.runCall` would require threading a
  second host table through `Exec.step`/`callFunc` and repairing the `Logged` commutation proofs —
  not an additive change to the signed closure. So the nine rows are `partial`.
* **No whole-chunk case exists** in any corpus for these hosts, and the corpus cannot supply one
  while the chunk path has no arm.
* **No kernel theorem** ties the payloads to `blst`; the differential suite carries that weight.
* **`alt_bn128_*` is untouched** and remains available to the parallel substream. `cryptoHostCall`
  has no alt_bn128 arm and a dispatch check asserts it stays `none`.
* The inventory generator's `lean_path_symbol` for these rows names
  `NearSpecV3.Wasm.CryptoHost.<host>`, but the real Lean constants are `hostP1Sum`,
  `hostPairingCheck`, … selected through `cryptoHostCall`. This is a pre-existing shared
  convention (the same shape appears on the already-accepted `ecrecover`/`p256_verify` rows), so
  it was left to the integration lane rather than changed here and risking a merge conflict.

## 9. Controlled breakage evidence

Two independent probes, both restored afterwards:

* **Pairing charge order** — reverting `pairing_check` to charge per-element from the *operand*
  `value_len` produced exactly four failures (`register 1 byte charges 0 elements`,
  `register 1 byte errors on length`, `register 577 bytes charges 2 elements`,
  `register 577 bytes errors on length`) and exit 1. The read-before-per-element order is
  load-bearing and is what the tests pin.
* **Dispatch** — deleting the `bls12381_p2_decompress` arm from `cryptoHostCall` produced exactly
  `BLS HOST FAIL: dispatch: p2_decompress selects an arm`, `147 total, 1 failures`, exit 1.

## 10. Next step (for the integration lane)

1. Thread `cryptoHostCall` into the chunk path as a second host table in `Exec.step`/`callFunc`,
   then repair the `Logged` commutation proofs. That is the only route to acceptance criterion 1
   for all nine rows; until then `partial` is the honest ceiling.
2. When that lands, supply one valid and one invalid whole chunk per host and commit the host
   result through the chunk's post-state root — the remaining acceptance work.
