## 1. The T1 segment system (item 1) [K]

`Templates.lean`. Templates `Tmpl = init | state | rt | wasm | final`; each has a meaning, a
relation on `RCM` configurations contained in `RSteps` (`meaning_rsteps`):

| template | lane | meaning |
|---|---|---|
| `init` | G | `MInit`: `init cb wb → c`, `CM.step (init cb wb) = .ok c` |
| `state` | B | `MState`: `eng I c →* eng I c'` through engine steps answered by the **empty** VM tape (`VFree`: `estepO (strictO [])`); consecutive segments merge (`mstate_trans`) |
| `rt` | F | `MRt`: `enter` (start call `q` from a non-final engine configuration), `next`, `resume` (the receipt step finished with the VM answered only from the tape) |
| `wasm` | A | `MWasm`: `CSteps q cc cc'` inside one call |
| `final` | G | `MFinal`: a `CM` run from `eng I ⟨.done out, _⟩`, `fin I out` or `gfin G` |

* **System.** `sys V A = digestSys Tmpl (Σ k, A.Tr k) V.bnd (sysHolds A)`: boundaries are
  `bndOf V.bnd x` (42-B digest of the `BndRec` encoding), opened by `absD`; `A : Airs` is the
  lanes' trace type and `Holds` per template.
* **Per-template obligations** (`TmplSound V A Bad k`, abbreviations `SegSoundInit`,
  `SegSoundState`, `SegSoundRt`, `SegSoundWasm`, `SegSoundFinal`):
  `A.Holds k d d' tr → Bad ∨ ∃ x x', bndOf V.bnd x = d ∧ bndOf V.bnd x' = d' ∧ Meaning k x x'`.
  `segSoundR_t1`: the five give `SegSoundR (sys V A) (Bad ∨ BndCollision V.bnd)`.
* **Wrap obligations.** `WrapInitSound` (`B_0` is the digest of `init (assemble s.ci secB s.secC) w`)
  and `WrapFinalSound` (`B_N` is the digest of a configuration passing `FinalOutPub s`); reference
  instance `t1Wrap` (`t1Wrap_init`, `t1Wrap_final`).
* **`e2e_sound_t1`**: `NvFaithfulE2E` + the two wrap obligations + the five template obligations ⇒
  `E2EStmt s ∨ Bad ∨ BndCollision V.bnd`. `e2e_sound_t1_bind`: for a view with well-formed records,
  the collision is a SHA-384 collision or a component-commitment collision.
* **Honest side.** `cm_decomp`: every `CM` run factors into template meanings (`init`; per engine
  step one `state` segment when its honest tape is empty, else `rt` enter + per call `wasm` +
  `rt` next/resume, via `estepO_honest`/`honestQ`; `final`). `TmplComplete V A k` (completeness per
  template) and `honest_chain`: an accepting run of an assembled claim gives a valid chain of the
  system whose root boundaries pass `t1Wrap`. `cut_roundtrip`: at every cut the record decodes
  back and the digest opens to the cut or there is a collision.

T1's actual run (interpreter trace, [M]): 13 `CM` steps — `init`, engine `start`, `txs` ×2,
`locals`, `delayed` ×2, `incoming` ×2 (the first with one VM call: `d3tiny.run`), `yields` ×2,
`done`, `fin`. Under `cm_decomp`: `INIT`, `STATE` (6 steps, mergeable), `RT` enter, `WASM`, `RT`
resume, `STATE` (3 steps), `FINAL`. Lane I's 7-segment plan maps onto it (its
"STATE(r1 up to VM call)" / "STATE(r1 resume)" are `rt` enter / resume; its two `WASM` cuts split
one `MWasm` by `CSteps.trans`).

## 4. `EngOvlInv.cur` (item 3, sub-agent, reviewed) [K]

`OvlVal.lean`: a value-length invariant `OV` over the same walk as `OvlInv` (every committed or
pending entry has a `Hard` key or a value `< 2^24` B). Proved bounds: pending counts (u32), nonces
(u64), global-contract nonce, delayed/yield indices (16 B), group metadata (49 B) and items (25 B),
and the Wasm write-back under the named class **`VmWritesShort`** (every write a finished
`vmCall` records is `< 2^24` B; `storage_write` fails above 4 MiB before recording — a statement
about `vmCall` alone). `IntakeOk.cur` is replaced by **`curHard`** (the same bound restricted to
`Hard` keys). `Hard` covers account, code, access keys, received data, postponed ids/receipts,
delayed and buffered receipts, contract data, yield timeouts/receipts, buffer index, bandwidth
state and global-contract code (each class was checked necessary by removing it). Because contract
data keys are `Hard` (state-init writes them too), `curHard` still covers contract storage values;
the substantive bounds left are receipt-size facts.

**Finding (spec vs nearcore).** `cur` is **not provable from the engine**: an incoming receipt is
validated with `validReceipt false` (`StorageExecution.lean:726`; `D2/Fees.lean:473` checks
`max_receipt_size` only in new mode, as nearcore's `ValidateReceiptMode::Existing` does), so a
witness-supplied action receipt of > 2^24 B (five 4-MiB-argument calls; the witness cap is
≈ 75 MB) is stored verbatim as a postponed or delayed receipt; likewise distribution receipts'
global-contract code. nearcore rules these out when the receipt is *created* (New mode, 4 MiB), a
fact about chain history, not about this chunk. Closing `cur` needs an intake-side hypothesis
"incoming receipts satisfy the New-mode size limit" (or lane B's circuit to admit longer values)
plus a receipt-size pass for the other `Hard` classes. Lane B's circuit form only (`fitsB`) is
affected: a run with such a value has no circuit boundary, a completeness limit.
