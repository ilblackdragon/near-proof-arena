## 1. The single-database QROM argument (item 1): it does not go through

Full text: budget doc §9. Arithmetic: `e2e_tree_targets.out`.

**Why it fails.**
* **(A) The inner proofs are not oracle transcripts.** Only the wrap is checked against H. Every
  inner proof is checked in-circuit with the concrete SHA-384. The identification of the two
  (A-IC) is withdrawn as false (`PROOF.md` §7.1).
* Theorem O (`aic-research/LEMMA.md` §2) rules out a query-only bound for hash-only recursion.
* **(B) No published QROM theorem covers a tree, even with the hash idealised as the oracle.**
  * The depth-free PCD theorem, CGSY24 (TCC 2024, ePrint 2023/1646), is classical and calls its
    relativized step an idealisation.
  * CDHZ (ePrint 2025/2166, Eurocrypt 2026) is QROM, but proves extraction for one step; its
    composition is sequential.
* **(C) S-19 is still open even for a single proof.**

**What I could instantiate.**
* The wrap alone: 2^−130.22 via CDHZ Thm 11.3 + 6.10 + 8.3, at ε_rbr = 2^−268.01. The conditions
  are in §9.2. This is membership in the NV relation, not the base statement.
* The rest of the tree: name a computational assumption, InnerSound(ℓ, τ = 2^128), per inner
  level (ENDPOINTS endpoint (c)).

**Per-proof union at N = 299,594 (depth 6, fan-in 8, plus wrap).**

| constants | ε_rbr needed | parameter cost |
|---|---|---|
| constants 1 | ≤ 2^−274.19 | +4 / +6 / +5 WHIR queries (final / inner / base model shapes); 2nd OOD in final r1 and r3; ≈ +6.3 KB final proof |
| CDHZ | ≤ 2^−282.73 | not reachable by parameters: LogUp 279.2, fold MCA 280.7, μ 282.1 |

* Black-box CDHZ per proof fails 128 bits for every N ≥ 7: its cubic floor is 2^−130.87 per proof.
* With the CMS19 constants at today's 2^−268.01, 128 bits holds for N ≤ 548, which covers the
  160-proof design point.
* No pinned parameter was changed.

**Paper sub-result [W, unreviewed]: S-17 (the sampler cap) can be removed.** Fold counter
exhaustion beyond J blocks into the move's bad set, with δ_J < 2^−1000. No implementation cap is
then needed.

**Citations.** Titles, authors and venues were checked on the ePrint landing pages. The PDFs were
blocked from this host (403), so theorem numbers are per the repo's PRIOR-ART reading, and §9
says so.

**Caveat.** Budget §0's "the wrap has no pinned parameters" predates lane D's D-5 wrap (main
`59fc5ddb9`, zk = 6, 328 KB). Re-check it against D-5's parameters.

## 2. NvAir exporter and model (item 2): partial

  **accurate**, not stale.
  * The old overlay's `verifier.rs` has `if b.bind || b.bind_child {} else if false { … }`, so
    `bind_child = true` was dead code.
  * `agg_node_program_binding`'s "positive control" mutates the node's own `P0..P3`, not a
    child's program.
  * Lane D found the same defect and fixed it (`e2e-tree.patch`).
  * My comment edit to the historical patch (`066e06a03`) was reverted (`55632f521`), because
    lane D keeps that patch unchanged as history.
* **Consequence for M11d.** `NodeInner`, which includes binding, was false for the old node, so
  `NodeExec` was unsatisfiable. The M11d theorems never assumed binding outside that premise, so
  they stand. Recorded in the `E2ENode` docstring.
* **Re-transcription (coordinator request), `E2ETree.lean`**, standard axioms only:
  * `node_bind`. It covers the anchor-set selector (`sel_mem`, `ones_of_fsum` over `Fp`),
    `flag_zero`/`flag_one`, sibling root equality, and equal levels. Conclusion: either every
    child is at the anchor level with its program root in the pinned set, or every child shares
    child 0's root and child 0 is BIND-bound (BIND faithfulness is a premise).
  * `normCell`/`padCell`, `one_template`. A chainable normaliser/PAD leaf sequence starting at
    `init` is exactly one template followed by PADs, and the root statement is the template's
    `init → done` statement.
  * `wmsg_inj` and `wrapT_composition`. Given V_d's `D_wrap` check, `aggWrapV` accepts or `H8`
    collides. `WrapExecT` is the open AIR obligation.
  * Non-vacuity examples.
  * `build_agg`'s statement logic is unchanged in the new overlay (diffed), so
    `compose_of_asserts` and `node_composition` stand.
* **Exporter: not delivered.**
  * The sub-agent wrote `nv-export/nv_export.rs` (dumps `vk.per_air[0].symbolic_constraints` and
    interactions as Lean data, with a SHA-256 of the canonical text) and `setup.sh` (private copy
    of the pq-agg tree).
  * It never ran: `export.log` is empty, and the agent stalled from 2026-11-03 10:57.
  * The draft is committed as-is. It targets the **historical** overlay. To use it, retarget it to
    the `e2e-tree` stack, which adds a `chain_start` bus in `uair.rs`.
* **No Lean NvAir model or sub-obligation proof was delivered.** The work plan:
  1. Run the exporter on the e2e-tree stack. NvAir is 74 columns and 49 interactions per row;
     expect a few thousand DAG nodes. Size it before deciding to elaborate the full table in
     Lean.
  2. `NodeTape`: the `PvD` op constraints (`uair.rs` `eval_alu`, about 15 constraints) plus the
     `mem` LookupBus, closed by `NvLogUpInt` and `y` = row index. It needs the program premise
     (`ProgramIs`). About 600–1,000 Lean lines.
  3. `NodeAsserts`: how `assert_eq`/`zero` compile (Sub + Zero ops), over the same memory
     argument. About +500 lines.
  4. `NodeSha`: the SHA AIR plus the slot/hash buses, which reuses the SHA lanes' work. Large.
  5. `NodeInner`: the recursive verifier gadget. Largest; it is the full F1–F6.
* **Vacuity guard** (coordinator, from lane A). The theorems quantify over `HoldsLogUp Pin.air`.
  That is non-vacuous only if `Pin.air` contains every table whose traffic closes NvAir's buses
  (Sha512Air, TableAir, ByteAir). A model with fewer tables must instead go through a bus-subset
  lemma plus a chip contract. Not yet exercised, since there is no model.
  `leafHolds_circ`/`circSeg` have the same caution: `segAir` must include every table the real
  verifier balances against.
