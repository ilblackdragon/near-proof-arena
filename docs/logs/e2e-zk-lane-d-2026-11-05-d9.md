## 1. Leaf geometry families (priority 1)

**Choice.** Families inside one setup, not "split L into S-size segments":
* The split needs lane A/B segment boundaries for D0a.
* The family route keeps one wrap setup and changes only an anchor set.

**Implementation.**
* `NEARPROOF_TREE_LEAF_FAMILIES=auto` (the default). Each class's template leaf is probed at
  (21, 20). Its family geometry is (lg NvAir rows, lg program rows), and classes with equal
  geometry share a family. `=one` gives the D-8 behaviour.
* Each family has its own `PAD_L^f`, `h_L^f` and `P_2^f` (template set = the family's classes +
  `PAD_L^f`).
* At setup creation every other family's `P_2` is generated over copies of one `PAD_L^f` proof,
  to size the shared node geometry (max over families × margin) and to fix `C_2^f`.
* Circuit (`e2e-tree.patch`):
  * `build_wrap_set` is the wrap over `{C_2^f}` via `anchor_set`; a single root gives the D-8
    program;
  * `build_node_star_set` is the level-2 set `{C_2^f} ∪ {C_padN}`;
  * test `tree_d9_wrap_set_debug` (2 threads, 1,817 s) accepts the root at positions 1, 2 and
    3 of 3; it rejects, by the constraints, a set without the root, a one-wrong-root set, and a
    wrong level. The 6 non-ignored agg/tree tests pass.
* A base dir is tried only as the classes whose base vk it has (`try_class`; the first run
  panicked when an L confirmation was tried at the S geometry).
