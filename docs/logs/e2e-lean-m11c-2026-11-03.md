## 1. `NodeOK` and `WrapOK` from the pinned programs

**The node program.** `build_agg` (`openvm-recursion-agg.patch`) does four things:
* it takes `k ≥ 2` children;
* it verifies each child in-circuit and reads the child's range statement `(ctx, a, e, s_a, s_e)`;
* it asserts continuity (same `ctx`, `a_i = e_{i-1}`, `s_a_i = s_e_{i-1}`);
* it exposes the tag-9 digest of `(f.ctx, f.a, l.e, f.s_a, l.s_e)`.

Steps 3–4 are `Stmt.compose`. `Stmt.compose` is already the Lean transcription of
`RangeStmt::compose` (`Aggregation/Statement.lean`).

`aggNodeV Acc rdigest` is this program as an `NvVerifier`. It accepts digest `d` and children
`(stmt, proof)` iff:
* there are at least two children;
* every child is accepted natively (`Acc`);
* `compose (stmts) = some out` with `rdigest out = d`.

**Proved:**
* `compose_chain`: if `compose` succeeds, the children's boundaries chain from `out.sa` to `out.se`.
  The proof is by induction through `composeFrom`.
* `nodeOK_agg`: this is `NodeOK`, now as a theorem.
* `wrapOK_agg`: this is `WrapOK`, derived from `NvFaithful` of the wrap circuit and the wrap's
  extraction `ExtractW`. The wrap program `aggWrapV` does four things: it verifies the root
  against its preimage statement, checks `ctx` against the claim digest, and runs `InitOK` and
  `FinalOK`.
* `leaves_of_acc_agg` is an induction on the recursion level. In the node case the extracted node
  trace gives the following, via `NvFaithful`:
  * accepted children;
  * a composed `out` with `D(out) = D(st)`;
  * `out = st` by `RangeBinding`, unless `rangeColl` holds.
* `nvFaithfulE2E_of_agg` and `e2e_sound_of_agg` hold with `Bad := BE.Any`.
* Non-vacuity: the node program accepts the chain `0 → 1 → 2` and rejects the swapped pair
  (`rfl` on `compose`).

**What remains, stated precisely:**
* `NvFaithful A.Pin A.D (aggNodeV …)` and `NvFaithful A.PinW A.DW (aggWrapV …)`. Five of the six
  sub-obligations in `NvFaithful.lean` are still open.
* `ExtractWG`, per accepted proof. Unless one of the bad events `hashColl`, `whirBad`, `gkrBad`
  or `rangeColl` occurs, the trace `ext π` read off the WHIR openings satisfies the key's AIR with
  the LogUp field balance:
  * for leaf template `k`, at `segPub π` with `segStmt (segPub π) = st`;
  * for the node key, at `pub π` with `D.stmt (pub π) = D(st)`, and every child has a lower level.

  `ExtractW` is the same statement for the wrap key. The QROM probability bounds are recorded in
  `BadEvents`: `Q²/2^337` for 42-B digests, `ε_WHIR·Q`, and `(ε_LogUp + ε_GKR)·Q`. They are not
  Lean theorems, because this library has no measure theory.
* `LeafHolds`: `S.Holds k` is the template AIR's `HoldsLogUp`. For the circuit's segment system
  this holds by definition.

## 2. Genesis segments

`checkSuccessor` routes a segment that contains a genesis block to `checkD2CoreGWith`. M11 took
that path in one atomic step (`init → doneG`).

**Slices.** These equalities are `rfl`:
* `checkD2CoreGWith = gPrefixK (gRest …)`;
* `gRest g = if !g.B2.isGenesis then checkD2CoreWith … else genAK g genB`;
* `checkD2CoreWithObs = d2IntakeK (fun I d => apply … >>= fun out => finD2K I d out
  (tailD2Orig I out))`.

**Machine.**
* **Main block not genesis.** The genesis block is a source block further back, and the checker
  delegates to `checkD2CoreWithObs`. `INTAKE` runs `gPrefixK` and then `d2IntakeK`, which builds
  an `Intake` with `d2 = some ⟨b2i, sched⟩`. Its engine program `I.prog` is the one
  `checkD2CoreWithObs` runs. The same `eng` steps follow, so receipt steps and mid-call Wasm cuts
  (`RCM`) apply unchanged. `FINAL` is `finStep I out`, which dispatches on `I.d2` to `finD2K`
  plus `tailD2New`: no outgoing reassignment, and `proposedSplit = none`.
* **Main block genesis.** `INTAKE` runs `genAK` and ends in the new configuration `gfin G`. `G`
  holds the stored genesis chunk extra, the root, and what the implicit transitions read. `FINAL`
  is `genB`: the implicit transitions on the genesis root plus the header comparison. It steps to
  `doneG`. This path has no main transition, so `genB` is the only remaining work.

**Proofs:**
* `cm_iff_gen : checkD2CoreGWith … = .ok () ↔ CMAccepts cb wb`, for both branches;
* `cm_iff`, with an unchanged statement, now uses it;
* `tailD2Orig_ok_iff`: the delegated header comparison equals `headerOk` on `tailD2New`;
* `d2IntakeK_post`: the delegated intake's record carries the decoded claim and header, and
  `d2 = some d`. `cm_done_header` uses it on the delegated path.
* `intakeK_post` now also gives `d2 = none`.

`rcm_iff`, `e2e_sound_r`, `e2e_statement_iff` and the downstream statements are unchanged.

**Boundary.** `gfin` has tag 3 and commits `G` through `ctxRoot` (§3). The delegated path's
configurations are ordinary `eng`/`fin`/`call` configurations.

## 3. The commitment `view`

`split : RConf → Parts` maps a configuration to a clear tag plus five components. `unsplit`
inverts it, and `unsplit_split` and `split_inj` show the components determine the configuration.

| component | content | field | lane |
|---|---|---|---|
| tag | `init 0, eng 1, fin 2, gfin 3, done 4, doneG 5, call 6` | `phase` | E |
| `CtxV` | `(cb, wb)`, `I`, `G` or `H` | `ctxRoot` (new) | B (`INTAKE`) |
| `StV` | engine position and receipt state without the output lists, recorder state; or the main output | `stRoot` | B (`StateM5a`: `Ws`, `Store`) |
| `OutV` | outcomes, outgoing receipts and proposals; or the final `Outputs` | `outcomeAcc`, `outRcptAcc`, `proposalsAcc`, `bwAcc` | B (M5d) |
| `VmV` | `K` | `vmAcc` | A/E |
| `WmV` | `(q, cc)` | `wasm`, `inCall` | A |

`ViewImpl` is the structure the lanes fill. It has one commitment per component, plus the clear
fields: claim digest, indices, clock and counters.

**The binding lemmas:**
* `viewImpl_binding`: given `WF` records, a boundary collision is a 42-B SHA-384 collision or a
  collision of one component commitment.
* `viewImpl_binding_bad`: this reduces `BndCollision` to `Bad` from the lanes' per-component
  reductions.
* `chainD_binding` / `coll_chainD`: a running list commitment
  `acc_{i+1} = bdigest (acc_i ‖ enc a_i)`, over an injective `enc`, is binding modulo `bdigest`
  collisions. It suits the accumulators and the call tape.

## Proof-engineering notes

* **Join points multiply code under `simp` or `split`.** Every `if c then x` without an `else`
  becomes a join point, and unfolding the join points duplicates the rest of the block.
  * `nat_walk` failed on whole slices, and `simp only [bind_assoc]` hit its step limit.
  * The fix is to cut slices right after such `if`s, so each slice ends in a call to the next one.
    This is the reason for `gPrefixK/B/C`, `genAK/AB/AC` and `d2IntakeK/…/E`.
* **Splits are `rfl` only when both sides keep the checker's own shape.**
  * Stating the split of `checkD2CoreGWith` directly with `genAK g genB` ran for more than 20
    minutes without finishing.
  * Splitting into `gPrefixK (gRest …)` first, and then proving `gRest_eq` by `rfl`, takes seconds.
  * The elaborated `return (← x)` is `x` itself, not `x >>= pure`.
* **The shared scratchpad can contain other sessions' files.** One generator picked up a foreign
  `tail.lean` from the shared scratchpad; this was found and reverted before any build. Temporary
  files now live under `/data/illia/nearproof-deps/tmp-laneE/work`.
