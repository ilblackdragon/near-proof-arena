## Done

* **3 corpus D0a chunks end to end** (`d1run/d1/00-h10006-s3`, `00-h10007-s0`,
  `d2corpus.v2/d2/05-h10042-s3`; 1–4 receipts): witness → base → L1..L4/L5 → FINAL →
  fresh-process verify. Packets 306,839 / 307,314 / 307,427 B. CPU 2,980–3,414 s per chunk on 16
  threads (shared host), peak 16.9 GiB. 23/23 negatives per chunk, including a wrong-witness base
  proof rejected by the verifier (`SumClaimMismatch`).
* **Verifier 7.65 s → 104–112 ms on one core** (fresh process, all checks). 99 % of the old time was
  recomputing the base proof's cached TAPE commitment (126 M-point codeword) from the claim. The L1
  circuit now binds the TAPE by its stacked opening at the transcript-derived stacking point u
  (WHIR-proved in-circuit); the verifier evaluates the public TAPE at u. Program check reuses the
  batch point. Same binary on the delivered v1 packet: 8.8 s.
* **Geometry:** these chunks need `ns19/lb6` recursion layers (L1 SHA AIR is 2^21 rows); the
  delivered `ns18/lb7` fails with `LayoutHeightExceeded{21,20}`.
* **128-bit:** every component ≥ 268.2 RBR bits (FINAL WHIR query bound binds), i.e. ≈ 2^-140 per
  layer at 2^64 quantum queries; `security_established=false` (A-IC + HANDOVER obligations).
* **Projection (model only):** 100 Tgas worst case 2.38 s on 8 H200 (meets ≤ 3 s), 1 Pgas worst
  case 10.56 s (5.6 % over ~10 s); the chain as run ≈ 0.66 s on 8 H200.

## Not done

* **Zero knowledge is not implemented.** `ZK-ARGUMENT.md` lists what leaks, the construction
  (salted leaves, off-hypercube trace masking, Libra-masked sumchecks, HVZK-WHIR, a hiding base
  commitment for the now-public u), a simulation sketch, and the gap (no machine-checked ZK
  statement; the repo's Lean pattern does not model the proof system).
* **ZK size:** HVZK-WHIR measured at 128-bit Johnson, rate 1/64 adds **+222–312 KB** (Plonky3
  3acc8b7, `zk128` example), not the 92.9 KB the prover-budget model assumed. A ZK packet would be
  ≈ 530–620 KB, over the ~400 KB accepted. The "128-bit octic crash" does not reproduce at this
  Plonky3 revision.

## Findings worth keeping

* One claim byte per chunk is not bound by the D0a relation: flipping it changes no public input
  and the Lean checker accepts the mutated claim with the same witness, so accepting the proof is
  correct; the negative harness takes its expected verdict from the reference checker.
* `head` column 72 is free on the last active row (transition-only constraint): witness
  malleability, not a statement change.
