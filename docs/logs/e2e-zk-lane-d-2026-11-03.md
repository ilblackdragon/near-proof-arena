## Verify in-process (sub-agent)

Goal: fresh-process FINAL verify < 200 ms on one core. Changes (no proof format, soundness check or
parameter touched; the trusted-setup pin and AIR pin are unchanged and checked first):

* **`statepublic` in process.** Its logic is now the library function
  `npudr::v3::statement::public_statement(&AirPublic, claim, hint)` (`examples/np-udr-stark-v2/source`);
  the example binary calls it and writes byte-identical `pubs.bin`/`pubmsgs.json`. `verify` calls
  it directly with the transmitted hint bytes (no temp dir, no subprocess); any preparation error
  still rejects ("claim/hint rejected", now with the reason). The STATEPUBLIC CLI argument is kept
  and ignored. The driver now depends on the classical crate (`manifest.py`, `Cargo.lock`).
* **AIR read once, public view only.** `npudr::airpub::AirPublic::from_json_slice` makes one

  30 ms → 1.5 ms. The unused reference-engine construction on the TAPE-eval path is skipped.

## Milestone D-2 (afternoon): full zero-knowledge masking of FINAL

Deliverables: `native/recursion/patches/zk-piop.patch` (`make_zk_piop_patch.sh`, applied by
`setup_e2e_verify_deps.sh` after `zk-pcs.patch`), `stark-backend/src/zk.rs`, driver
`zk-selftest` / `zk-layout` / `NEARPROOF_ZK_GUESS`, `e2e/scripts/{run_zk4,run_zk5_extra,run_zk_guess}.sh`,
ZK-ARGUMENT.md rewritten, README §0, plan §5.0. Mode `WhirLevers::zk = 5`.

* **Built (all PIOP fields masked):**
  * GKR: a masked root sumcheck replaces the half-sum and `q_0` messages. Levels get off-cube
    masks in the last coordinate, and every layer gets a Libra mask.
  * Batch sumcheck: a Libra mask whose uni-skip mask is free in X. Each column is masked in its
    AIR's last variable; that round's degree goes to 2d and its tables are two rows. Per-AIR
    LogUp terms are aggregated (coefficients 1 and μ), so none are sent.
  * Stacking: sparse mask claims plus a two-column Libra mask.
  * Public program columns are unmasked, because V_d checks them. The first full-ZK run, which
    masked them, was rejected by V_d.
  * 15 mask columns: 12 stay a pure WHIR pad, and 3 carry the PIOP masks.
* **`zk-selftest`** runs in the FINAL configuration on toy AIRs with mixed heights, tight chunks
  and splitting. Prove, verify and the codec round trip all pass, and 103–205 tampers are
  rejected per configuration (`results/zk/zk-selftest.txt`).
* **Split packing fixed (item 3).**
  * Bug 1: halves were re-queued at the front, so a later full-size slice landed misaligned.
    That was the 11-03 `FinalSumMismatch`. A toy with tight heights plus splitting reproduced it.
  * Bug 2: the first fix re-queued every half behind the larger slices. That shredded slices
    into gap-sized pieces: about 10^4 slices, a 62 s `verify_proof_shape` and a 66 s verifier.
  * Final rule: halves fill only existing gaps; a piece that needs a new column waits behind the
    larger slices. FINAL now has 68 columns and 1,537 slices, and the layout takes 0.1 ms.
* **Measured on 3 chunks (items 1 and 4):**
  * Packets 319,695 / 320,464 / 319,779 B: −5.9 to −6.5 KB against `zk = 2`, +12.4 to +13.2 KB
    against non-ZK.
  * FINAL prove 528–763 s at host load 13–19.
  * Fresh-process verify 40–50 ms on one core; the FINAL check is 24–26 ms.
  * 21/21 negatives per chunk; minimum 268.2 bits per round.
* **ZK argument (item 2):** the simulator and hiding error are in ZK-ARGUMENT.md §6:
  ε ≤ 2^-185 + ε_D + ε_E.
  * Proven: Lemmas A–C (Libra, level masks, column masks) and Lemma S (the F-span of an
    evaluation functional is EF, ≤ 2^-154).
  * **Open:** Lemma D (joint F-rank of the stacking-mask functionals of base-field columns) and
    Lemma E (per-column joint absorption of opened symbols and the stacked opening; inherited
    from the PCS layer).
  * So `zero_knowledge_established=false`.
  * Fix for both: batch WHIR with the stacking final coefficients plus a μ-power pad, so no
    individual stacked opening is sent, which also saves about 3.3 KB. Use an EF-valued stacking

  * `zk-diff` of two `zk = 5` proofs from the same L4: only the shape, public values, the
    zero-bit PoW witness and structural zeros agree.
* **Item 5, chunk 1 FINAL:** 268 bits → 319,695 B; 274 bits → 325,051 B (+5.4 KB, queries
  [47, 43, 31, 25], minimum 274.0, verify 39 ms).
