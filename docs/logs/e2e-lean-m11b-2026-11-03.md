## 1. Mid-call cut

**Call machine.** A FunctionCall reaches Wasm only through
`vmCall wasmFuel = .ok (runCallWithLimits …)`. `CallConf` has three forms:
* `pre`;
* `ent p k r n`: entry `k` (`start mi` or `method`) of the prepared module `p`, with interpreter
  result `r` and fuel `n`;
* `fin r`.

A step at `ent p k (.cont s) (n+1)` runs exactly one `Wasm.step`. The `inCall` boundary is
`ent p k (.cont s) n`.

**The prefix is the checker's code.** `runCallG` is `runCall` verbatim (its local `let`s lifted to
`emptyStOf`/`extOf`/`nopOf`/`loadedOf`/`adjustSt`), with its finished results and its first-entry
point as parameters. `runCall_eq_G` is `rfl`.

**Denotation.** `runCallG_nat` carries the denotation through the prefix, and `cden_step` shows
each step preserves it. `csteps_fin_iff` is the result: `CSteps q .pre (.fin r) ↔ callResult q = r`.

**Segments.** `csteps_seg`/`csteps_foldSegments`: `seg cfg p a s = .cont s'` (resp. `foldSegments`)
is a call-machine run from `ent p k (.cont s) n` to `ent p k (.cont s') (n - a)`.
`cden_foldSegments` is `Wasm.run_foldSegments` on the machine.

**The receipt step with the VM as a parameter.** Seven layers are copied verbatim: `fcW`,
`applyActionW`, `actionLoopW`, `applyActionReceiptW`, `processReceiptW`, `processWithTotalsW` and
`drainW`/`processWithInstantW`. Each takes its direct callee as a parameter, and `fcW` takes the
VM call in place of `vmCall fuelOf`.
* At the original callees the copies are the originals. Five are `rfl`; `actionLoopW_std` and
  `drainW_std` are inductions. `pwO_std : pwO vmStd = processWithInstant`.
* Every layer is monotone in its callee (`MLe`: every successful result is a successful result of
  the other side). The tactic `mono_walk` proves it over each copied body: it descends binds, splits
  `if`/`match` together, and handles the one `try … catch e => throw …` (`MLe.tryCatch_throw`).
  Composed, this is `pwO_mono`.
* `stepMO` is `stepM` with the receipt body as a parameter (`stepMO_std`, `stepMO_mono`).
* `estepO_sound`: an oracle step that succeeds with an oracle below the checker's VM (`OLe`) is the
  engine step.

**`RCM`.** `RConf.call I c K q cc`: engine configuration `c`, answered queries `K`, current query
`q` at call configuration `cc`. The steps are:
* `base`: a `CM` step;
* `enter`: start a call;
* `wasm`: one call-machine step;
* `next`: append `(q, r)` to `K` and start the next call;
* `resume`: complete the receipt step with the strict oracle `strictO K`. An unanswered query
  fails, so the STATE template never runs Wasm.

Soundness uses the invariant `RInv` (`Steps a (eng I c)`, the answers in `K` are the calls' results
by `csteps_fin_iff`, and `cc` is reachable from `pre`). The results:
* `rsteps_sound` and `rsteps_of_steps`;
* **`rcm_iff : Tier.rel .allFeatures cb wb ↔ RCMAccepts cb wb`**;
* `rsteps_seg`/`rsteps_foldSegments`: Wasm segments are `RCM` runs between `inCall` boundaries;
* `rsteps_through_calls` (non-vacuity): a receipt step completed by the answers of `q₁…q_m` is
  reached through every call-machine configuration of every call;
* `e2e_sound_r`: `e2e_sound` with `SegSoundR` against `RSteps`, so segments may begin and end
  mid-call. The wrap obligations are taken on the `CM`-level view `RSegSystem.toSeg`.

## 2. Concrete boundary

**Record.** `BndRec` holds the §3.2 fields:
* `claimDigest`; the phase, block, receipt and action indices; `inCall`; `t`; `stRoot`;
* the chunk gas and burnt totals and the receipt's counters;
* the output accumulators;
* `vmAcc` (the digest of `K`);
* `wasm : Option WasmBnd`: `pc`, `S`, `stackRem`, fuel, the frames/globals/registers/VMContext/
  promises digests, `memRoot` and `memPages`, and `codeRoot`/`funcRoot`.

**Codec.** Codecs are composable (`natC`, `bytesC`, `boolC`, `pairC`, `listC`, `optC`, `mapC`),
each with the law `dec (enc a ++ rest) = some (a, rest)`. `BndRec.decode_encode` is the round trip
on `WF` records, and `BndRec.encode_inj` follows from it.

**Hash.** `sha384` is SHA-512's computation from the §5.3.4 IV, truncated to 48 bytes. It has
`sha384_length`, and `sha384_abc` (the FIPS 180-4 example) is checked by `decide +kernel`.
`bdigest` truncates to 42 B (U-10).

**`abs`.** `absD view` opens a digest by choice; `view : RConf → BndRec` is a parameter. The
results:
* `absD_bndOf`: `absD view (bndOf view x) = some x ∨ BndCollision view`;
* `bndCollision_split`: a SHA-384 collision on distinct encodings, or a `view` collision;
* `segSoundR_digest`: segments that open both digests to `RSteps`-connected configurations give
  `SegSoundR` at the digest boundary with `Bad := BndCollision view`.

## 3. Obligation 1 from `NvFaithful`

`ZkFormal` already requires `NearSpecV3`, so the v3 package cannot import `ZkFormal` (that would
be a cycle). The link therefore lives in `zk-formal`.

`nvFaithfulE2E_of_nv` derives `NvFaithfulE2E S W FinalVerify Bad` from four hypotheses:
* `NvFaithful A.Pin A.D A.V`: the node circuit, whose native verifier checks a list of children
  `(B_in, B_out, proof)`;
* `NodeOK`: an accepting node verification accepts each child, and the children chain from
  `B_in` to `B_out`;
* `Extract`: knowledge soundness / QROM. An accepted proof is a leaf with `S.Holds`, or a node
  trace satisfying `HoldsLogUp` for the node AIR with that statement and lower children, or `Bad`;
* `WrapOK`.

The proof is an induction on proof height (`leaves_of_acc`). `e2e_sound_of_nv` composes it with
`e2e_sound`.

## Proof-engineering notes

* **A direct equality between `cden (preConfK …)` and `runCall` is infeasible.** The two terms
  use different auxiliary matchers.
  * Splitting both sides gives a cross product of goals.
  * Leaf `rfl`s make the kernel unfold `run`/`callEntry` and time out.
  * The fix: `runCallG` (one copy, shared matchers), with `runCall = runCallG id tailRun` by `rfl`
    and naturality `runCallG_nat`. Each module now checks in seconds.
* **`dsimp only` on goals that contain `payPer`/`payBase`/`prepare` can stall.** It tries to
  reduce matches whose discriminants are these functions. The final proofs avoid this.
* **Fuel must not be a numeral the kernel can see.** `wasmFuel … + 1000000` reduces by
  successors. `cdenE` therefore takes the fuel as a variable, and `cden` instantiates it.
