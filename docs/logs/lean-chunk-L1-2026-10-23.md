## The finding that motivated this

`gAlpha = 2 ^ 22 * 822756 ≈ 3.45 Tgas` is derived from **one np-udr-stark proof's maximum table
height** (`2^22` rows) times the cheapest Wasm operator's gas (`regular_op_cost = 822756`). The
protocol's own per-chunk limit is `max_gas_burnt = 1 Pgas`, which is **289.8× larger**.

So the current D3α domain excludes protocol-valid chunks for a reason that is purely about the prover.
Plan §4 L1 calls that out explicitly: the relation must "have no `G_α` or other bound derived from one
prover's table height, width, recursion shape or performance budget."

## What I deliberately did NOT do

**I did not change `gAlpha` or `RelD3`.** `G_α` is a checked condition (`e.g_alpha`) in the signed
`near-chunk-v3` challenge, generated by `spec/tools/build_challenge_draft_v3_chunk.py:104`, and
`make pin-check` verifies those hashes. Editing the constant would silently change the statement a
candidate is admitted against — exactly the failure mode the plan's shared rules warn about. The
successor is defined alongside, and `pin-check` still passes (verified after the change).

**I did not claim the successor admits strictly more chunks.** An earlier draft asserted
`RelD3Proto → RelD3` fails as a theorem. It does not follow from the caps alone: the relations differ
only in the cap value, so the disagreement set is "chunks whose function-call gas falls in the band",
and whether that set is non-empty is a fact about real chunk data. I removed the assertion rather than
leave a `sorry` or an overclaim. The module doc records why.

## What is genuinely open for L1

1. **Exhibit a band chunk.** Find or construct a protocol-valid chunk with function-call gas in
   `(3.45 Tgas, 1 Pgas]` and show `RelD3Proto` accepts what `RelD3` rejects. Without one, the widening
   is structural, not demonstrated. This is the cheapest next step and it makes the negative result
   real.
2. **Tier nesting.** Prove each successor tier's inclusion in the relation and the declared nesting
   between tiers. `rel_mono` already lifts rung relations to the challenge statement; the successor's
   equivalent is not stated.
3. **Old-to-new agreement.** Prove agreement on the overlapping domain (gas ≤ `gAlpha`) or document an
   actual semantic correction with a counterexample. The overlapping part should be mechanical since
   only the cap differs — but "should be" is not a proof, and it needs stating.
4. **Evaluator termination and fuel.** Plan §4 L1 notes "a larger numeric cap alone is insufficient:
   audit evaluator termination, fuel, stack safety and full-size resource use." Nothing in this lane
   addresses that. Raising the cap 290× means executions that previously never ran now do, and the
   spec's evaluator must terminate on them — untested.

Items 2 and 3 are proofs over the existing checker. Item 1 needs real chunk data. Item 4 is the one
that could invalidate the whole approach and is not started.
