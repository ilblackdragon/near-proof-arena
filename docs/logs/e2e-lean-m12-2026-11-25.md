## Item 1: F3-2, the clear-field convention (decision implemented)

Integrator decision: running counters carried, only irrelevant fields cleared, header outputs at
`done`. Implemented as `ViewE.clearE` (table in the file and in plan §3.5 "M12"). The only freedom
was which fields count as "not a function of the configuration"; those stay constant, each with a
reason: `claimDigest` (the decoded `Intake` does not determine `S`; the leaf statement's `ctx`
carries it), `blockIdx` (fixed by `I`), `actionIdx` (the engine's receipt step is atomic; `|K|`
counts VM calls, not actions), `t` (per-segment memory-checking clock; in-call progress is
`wasm.fuel`), `rBurnt`/`rUsed` (would vary with the Wasm state inside a call, contradicting
`ClearCall`; gone after `resume`). The cleaner alternative of the task statement ("take the totals
from the `stRoot` opening", F3-2's second option) was not chosen: it puts lane B's `rest` opening
into lane F's resume leaf, while the carried fields cost nothing (the clear fields carry no binding
obligation: `viewImpl_binding` reconstructs a configuration from the components alone).

Re-checked against the lanes' templates:
* lane A: `ClearCall (vT1 …)` is still `rfl`; `vT1_blind` needed `SB.setArgs_ctx` (the call's
  clear part reads `q.ctx.prepaidGas`). `WasmBase` + `wasmbase-tool` build (below).
* lane F: `RtView.clearEnter` holds for `clearE` with `pre q = u64c q.ctx.prepaidGas`
  (`clearE_enter`); lane F's `T1Enter` uses its own view `V1` (unchanged). Resume's
  `resumeCons` agrees with `clearE` on `gasUsed`/`gasBurnt`/`compute`/`balanceBurnt` (in = `RX`

  (today copy / `RX.vb` / `RX.vu`). Lane F's AIR is not changed here (it changes the measured
  leaf).
* lane G: no Lean statement of lane G's fixes the clear fields (FINAL exposes `ctxD`/`outD`
