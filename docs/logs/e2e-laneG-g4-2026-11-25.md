## Design decision

The suggested shard-id match (slot header `shard_id` = claim shard id) is **not** what the checker
does: the intake reads `B2.slots[Lmain.index mainShard]`, a *position* from the layout's
`id_to_index` map, and the checker never checks that the slot at that position carries that shard
id (T1: shard 3 is at index 5). Matching by header shard id would need a checker change, so it
was not used. Instead the AIR computes the checker's index from the layout bytes (section C,
public), restricted to class E1 (one epoch record), where the walk has no layout boundary and
reduces to the D2 rule. All 19,007 `d3` claims are E1 (scanned with `t1/stmt.py`).
