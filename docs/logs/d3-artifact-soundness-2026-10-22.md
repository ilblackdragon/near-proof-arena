# D3 artifact soundness: `RelD3` attached to the shipped verifier binary

Lane: `pq-d3-artifact-sound`.  Date 2026-10-22.  HEAD base `229518416`.

Evidence classes: **[K]** kernel-checked here, **[M]** measured here, **[S]** stated, **[O]** open.

## What was already true and what this adds

`examples/reexec-v3-d3` is a complete D3α candidate: `out/prepare`, `out/prove`, `out/verify`, and a
Lean certificate (`ReexecV3D3.certificate`) whose type is generated by the judge.  Its admission
statement (`Obligations.admission`) was already proved axiom-clean.  What was **missing** is the
statement the D3 goal actually asks for: *the installed binary accepted ⇒ `RelD3`*, as a named,
kernel-checked lemma rather than a definitional coincidence a reader has to notice.

`formal/ReexecV3D3/ArtifactSound.lean` adds it.  Eight theorems, all `[K]` with axioms
`{propext, Classical.choice, Quot.sound}` and `#guard_msgs`-guarded in the artifact's own build:

| theorem | statement |
|---|---|
| `relTier_d3a_eq` | `NearSpecV3.RelTier .d3a cb w = D3.RelD3 cb w` (definitional) |
| `wfClaim_relTier_d3a_eq` | `WfClaim.RelTier .d3a c w = D3.RelD3 c.1.encode w` (definitional) |
| `artifact_sound_decoded` | accepted ⇒ `∃ c, decode cb = some c ∧ RelD3 c.1.encode pb` |
| `artifact_sound` | + canonical claim bytes ⇒ `RelD3 cb pb` |
| `artifact_binding` | `(∀ c, decode cb = some c → ¬ RelD3 c.1.encode pb) ⇒ deployed ≠ true` |
| `artifact_sound_tier` | accepted ⇒ the declared tier relation `RelTier .d3a` |
| `artifact_sound_chunk` | accepted ⇒ the unified challenge language `RelChunkV3` |
| `artifact_complete` | tier-domain claims have an accepted, bounded, `RelD3` witness |

## Why the proof attaches to the real artifact, not a shadow

`build-recipe/build.sh` compiles `Model.verifier.run` into `out/verify`; `Model.verifier.run`'s body
is `check` (`Model.lean:22-23`).  `deployed_eq` proves `deployed pub cb pb = check cb pb` by `rfl`,
so the binary and the proved function are **the same function**.  `ArtifactSound` closes the last
link by unfolding `RelTier`'s `.d3a` branch, which is `D3.RelD3` verbatim
(`ChallengeChunkV3.lean:56-63`).

`Certificate.lean` now imports `ArtifactSound`, so the artifact's own certificate build type-checks
the D3 soundness chain — `lake build ReexecV3D3.Certificate` reports **156 jobs** including
`✔ Built ReexecV3D3.ArtifactSound` and `✔ Built ReexecV3D3.Certificate` [M].

## The honest limit of the soundness statement [K]

`artifact_sound_decoded` states the relation on `c.1.encode`, not on `cb`, deliberately.
`check` runs `Read.check (WfClaim.decode cb).encode pb`, and `decode cb = some c` does **not** imply
`c.encode = cb` — the relation is about the decoded chunk, which is the object nearcore validates.
`artifact_sound` gives the `cb` form only under the extra hypothesis that the accepted bytes are
already canonical for their decode.  Stating it without that hypothesis would have been false.

## End-to-end executable path [M]

The pipeline runs on real fixtures from `oracle/fixtures/v3/public-chunk-v3`:

```
$ ./out/prepare --params params.bin --out pub          # exit 0, writes pub/public.bin
$ ./out/prove   --public pub --request … --witness … --claim-out … --proof-out …   # exit 0
$ ./out/verify  --public pub --claim … --proof …       # exit 0  (accept)
$ ./out/verify  … --claim <1-byte mutation> …          # exit 1  (reject)
$ ./out/verify  … --proof <1-byte mutation> …          # exit 1  (reject)
```

* **Positives: 172/172** D3 cases in the public set proved and accepted, 0 rejections, 0 prover
  failures.
* **Negatives: 115/115** D3 rejection cases rejected *by the verifier* under cross-pairing (a
  rejection's own claim bytes paired with a proof valid for a different case), 0 bad accepts.  The
  honest prover also refuses all 115, but the cross-paired run is the one that measures verifier
  binding rather than prover-side filtering.

## Preparation is executed on the verifier side [K]

This is the "chunk → preparation" link and it is real, not a stub.  `Read.check`
(`ReadCanonDefs.lean:53-58`) runs `Logged.checkD3Reads cb w`, which is the **whole** `checkD3` —
including `Wasm.prepare` and the D3 execution — and then requires byte equality with the re-encoding
of the recorded-store read set it just observed.  `Logged.checkD3Reads_fst` and `checkD3L_eq`
(`NearSpecV3/Logged/D3LSpec.lean:206`) tie that run to the trusted `checkD3` by an equation, not by
assumption.  So acceptance is a statement about an actual preparation-and-execution run.

## Remaining open items

* **Succinctness [O].** The verifier is deterministic witness re-execution, not a succinct proof
  system (`Model.lean:6-11` says so explicitly).  Soundness and binding are closed; a STARK-style
  D3 AIR is not.
* **The join [O].** `ZkFormal.PQ.StatePort.JoinFold.join_additive` is still
  `intro … exact hrel` — it proves `RelD1a → RelD1a` and never touches `RelD3`
  (`JoinFold.lean:82-84`).  The honest replacement is `ZkFormal.PQ.Join.Statement.Compose`
  (`:641-642`), still stated-not-proved.  The proven fragment that does real work is
  `ZkFormal.PQ.Join.Fold.relD3_of_checkD2Core` (`:211`) with
  `Coverage.coverage_pv86` (`:146`), whose premises `hagree`/`hstate` remain open.  This document
  does **not** claim the join is closed.
* **No D3 AIR [O].** `nearAirV3D3`/`rcptV3D3`/`airD3` remain 0 hits in `spec/` and `zk-formal/`.
