Continuation of `pq-if2` (`55fab1e0f`, the spec steps) and `pq-d3-air` (`ce968bfc3`, storage hosts).
Those closed the *spec* and the *host table* for link 1 of `pq-d3-chain-gap-2026-10-21.md`; this

## 1. The `IF` table (`Chips.IfC`) [K]

A separate table, for the repo's own reason: `CTRL` must stay **byte-identical**, and `if` has the
opposite polarity to `fJif` (`br_if` jumps on non-zero; `if` falls through on non-zero). Same
precedent as `ChiAir`/`ShaAir`.

| column group | count | meaning |
|---|---:|---|
| header | 5 | `pc, ts, S, h, fee` |
| selector | 1 | `f_if` (bit) |
| `tgt` | 1 | the **false** target, `elseOf + 1` |
| condition | 2 | `c0, c1` (the popped i32's low limbs) |
| `tc, hc` | 2 | producer time and the `timeChk` witness |
| `inv` | 1 | the non-zero witness |
| frame | 2 | `fr_sb, fr_cid` |

`pcNext = nz·(pc+1) + (1−nz)·tgt` — **the polarity is in one expression**, and that is the whole
semantic difference from `fJif`'s `nz·tgt + (1−nz)·(pc+1)`.

Two constraints only: `bool f_if` and `(c0+c1)·(1−nz) = 0`.

**The design finding.** `if` has two successor *shapes* but only **one** AIR target. `matchBlocks`
writes `elseOf[i] = endOf[i]` when the `if` has no `else`, so both shapes send `elseOf + 1`. The
label-list difference (no-`else` pushes nothing) is **checker-side data**, not an AIR column. That
is why `tgt` is one column and not two.

## 2. The checker extension (`WasmBase/IfCheck.lean`) [K]

`HostCheck.lean`'s "extend, don't touch" discipline: `kindOf`, `analyze`, `verifyAt`, `recordOf`,
`check`, `checkModule` are **unchanged**, so every existing proof and table index keeps its meaning.

| new definition | mirrors | why |
|---|---|---|
| `ifStep` | `.block`'s arm | pops the condition, returns both successors and their labels |
| `analyzeIf` | `analyze` | one extra `.if_` arm |
| `verifyAtIf` | `verifyAt` | both arms must agree: `pc+1` and the false target |
| `recordAtIf` | `recordAt` | emits the `IF` record |
| `checkIf` / `checkModuleIf` | `check` / `checkModule` | the non-host flavour |
| `analyzeIfH` … `checkModuleIfH` | `HostCheck`'s four | **the composition that matters** |

Two proved facts about `ifStep` are the safety net:

| lemma | statement | axioms |
|---|---|---|
| `ifStep_pop` | both shapes pop exactly one operand | `[propext]` |
| `ifStep_noelse_ls` | `elseOf = endOf` ⇒ the false successor pushes **no** label | `[propext]` |

`if_sound` (in `Local/Simple.lean`, next to `ctrl_sound`/`stack_sound`) is the row-level fact:
`f_if` is a bit and `nz` is forced from the condition — std3 axioms.

## 3. The composition was the real blocker [M]

Neither extension alone puts a contract in domain:

* `checkModuleH` rejects `.if_` (that is the whole reason for this lane);
* `checkModuleIf` rejects **every** real contract, because all of them import hosts;
* `d3tiny`'s closure needs `input`/`register_len`/`read_register`/`storage_write` **and** one `if`.

So the deliverable is `checkModuleIfH`: `if` and host imports together. Verified by the debug
harness — each function passes `checkIfH`/`structOkIfH`/`recordAtIfH` individually, and the module
check fails only at its own import condition.

## 4. A spec point that matters: P3, not "all imports are hosts" [M]

`checkModuleH` requires **every** import to be a host function. `d3hostx` imports `ecrecover` and
never calls it, so that condition rejects a contract the spec places **in** D3α: per
`spec/near-chunk-validation-d3.md` §10.0a **P3**, an excluded host is out of domain *when called*,
not when imported.

`checkModuleIfH` therefore uses `calledImportsOk` — "every import the checked closure **calls** is a
host" — instead. `recordAtIfH` already refuses a `.call` to a non-host, so the two together are
exactly P3. Without this change `d3hostx` (and every contract that merely imports a curve function)
would be wrongly rejected. **This is a small semantic correction, not a loosening**: no additional
execution becomes representable.

## 5. The AIRs stay byte-identical [K]

| AIR | tables | change |
|---|---:|---|
| `wasmBaseAir` | 22 | **none** |
| `wasmBaseHostAir` | 26 | **none** |
| `wasmBaseIfAir` | 23 | + `IF` |
| `wasmBaseIfHostAir` | 27 | + `IF` |

The two new AIRs are separate values, so the host tables keep indices 22–25 and every host proof
(`HOST`, `HOSTO`, `HOSTT`, `HOSTB`, `REG`) is untouched. Verified by exporting all four and counting.

## 6. Rust `tracegen` [M]

`OP_IF = 0x106`; the `IF` row pops the condition, sets `f_if = 1`, `tgt = rec[4]`, `c0/c1/tc/hc`,
`inv`, and selects `next = if c.val ≠ 0 then pc + 1 else tgt`. The table is created **only** when the
AIR has `IF`, and padded with `f_if = 0` rows, so the base and host paths are unchanged.

The one unrejected tamper is `pub.result+1` on an **arity-0** program: `Boundary` gates the result
receive on `pubNres·(2−status)`, so at arity 0 the result is structurally unconstrained. That is
pre-existing and unrelated to `if` (the same case is guarded on arity-1 programs and does reject
there); recorded rather than "fixed", because the fix is a statement change, not an `if` change.

## What is still open (link 1 remains incomplete for *most* contracts)

1. **`else` as a first-class row** — not needed: `step_else` shows it is the existing `Ctrl.fJump`,
   and the checker handles it by the label it pushes. Nothing to add.
2. **`btResults` non-empty** — `ifShapeOk` restricts to no-result `if`, which covers every real
   contract's branch position. Result-carrying `if` needs the height arithmetic and a stack push.
3. **`d3rich`**: `loop`, `memory.grow`, `call_indirect` — separate AIR work, not `if`.
4. **`step_if_noelse`** — the false-arm-without-`else` spec lemma. `step_if` covers the true arm and
   `ifStep_noelse_ls` already supplies its label fact; the lemma itself is the remaining proof.
5. **The full `RowFacts` row lemma for `IF`** — `Main/RowIf.lean`, mirroring `RowCtrl.lean`. This is
   what makes `Holds (wasmBaseIfAir …) ⇒ RelW` go through, i.e. the soundness leg. `if_sound` is its
   local half; the STATE/CH/FETCH plumbing is mechanical but not yet written.
