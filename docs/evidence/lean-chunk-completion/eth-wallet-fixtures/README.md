# Legacy magic-hash ETH wallets in whole chunks (row `L0-D3-006`)

Validator-produced chunks from the pinned nearcore `44f7ae6cd7ef08bab604e20a473bf77e35d4c993`
(PV86). They were generated by `oracle/v3-successor` with a new opt-in cross-family scenario
(`NEAR_SUCCESSOR_SCENARIO=eth-wallet`, `src/xfam.rs` + `src/ethwallet.rs`). Every honest chunk and
every mutant is judged by the cold nearcore validator. Lean computes; nearcore's results are never
inputs.

The row's branch is `RuntimeContractIdentifier::resolve` (`runtime/runtime/src/contract_code.rs:56-76`):
an ETH-implicit account whose local code hash is a legacy wallet **magic** hash runs the chain's
global wallet (`eth_wallet_global_contract_hash(chain_id)`) at PV86. On `allFeatures` this is
`Successor/StorageExecution.lean` `resolveCode` → `D3.L4.Rci.resolve`. Such accounts exist on
mainnet only from before PV83, so a PV86 test chain needs them in genesis.

**Result: 10,650 cases over 8 seeds. `allFeatures` has 0 accept/reject disagreements with cold
nearcore and 0 accepts of a nearcore reject. Blind replay matches nearcore on 908/908 gradable
honest chunks. A checker with the redirect ablated disagrees on 609 rows, 22 of them accepts of a
nearcore reject. No Lean change was needed.**

## The genesis

nearcore accepts the genesis: `validate_genesis` (`core/chain-configs/src/genesis_validate.rs`)
checks supply, duplicates and keys, not code hashes. The records are what
`action_implicit_account_creation_transfer` wrote before PV83 (`actions.rs:251-270`, `else`
branch): an `Account` with `AccountContract::Local(sha256(magic))` and a `Contract` record holding
the magic bytes `"near" ‖ base58(sha256(wallet wasm))`, and no access key. The scenario creates one
such account for each of the four variants nearcore's `LegacyEthWallet::resolve` knows (mainnet,
testnet, old testnet pv70, localnet). The addresses come from secp256k1 keys
(`derive_eth_implicit_account_id`), so the wallet accepts their Ethereum signatures. The genesis
also holds three controls:

* an ETH-implicit account with ordinary local code (`xfam`), which stays local;
* an ETH-implicit account with no code;
* a **named** account holding the mainnet magic bytes (not ETH-implicit, so it stays local; the
  bytes are not a Wasm module).

The genesis code hashes equal Lean's `walletMagicHash` pins (UQ-007): for example, mainnet is
`77CJrGB4…` and localnet is `5Ch7WN9G…`. The chunk outcomes below show nearcore resolving each of
the four to the global wallet. `src/ethwallet.rs` also has a crate test asserting each hash resolves
through `near_wallet_contract::wallet_contract`. That test was not run for this evidence, because the
test build pulls the whole node.

## Scenarios

`eth-wallet` (default table, 4 seeds 701–704, 110 blocks, chain shapes 0/1/2/6, gas price 10^8 or 0):

1. `s3ewg` deploys the localnet wallet as a global contract by hash (the chain id
   `arena-v3-local` is not mainnet/testnet, so its global wallet hash is `sha256` of the localnet
   wasm, `lib.rs:87-104`). Relayers transfer 1 NEAR to each wallet.
2. Twelve rounds, 7 blocks apart. Per round and wallet, relayers on shards 1–3 submit:
   * one `rlp_execute` that returns a promise. Its EIP-2930 transaction (EVM chain id 399, signed
     with the wallet's key) asks for a `transfer` to a named account, a `functionCall` (`noop`) or a
     failing `functionCall` (`fail`) through the wallet, or a plain Ethereum transfer to the next
     wallet;
   * one failing call: wrong signer, wrong EVM chain id, malformed JSON arguments, a missing
     method, a deposit on the view `get_nonce`, or a `#[private]` callback called from outside;
   * a direct `get_nonce` (with a 0.1 NEAR transfer in the same receipt on even rounds);
   * one call on each control account.

`eth-wallet` + `NEAR_XFAM_VARIANT=eth-wallet-predeploy` (4 seeds 791–794, 12 blocks): the global
wallet is never deployed; relayers call `get_nonce` on the four wallets and the controls.

Ethereum nonces are predicted per wallet. A misprediction, for example after a dropped
transaction, makes the wallet answer with an error value. That is still a valid case and is counted
below.

### What nearcore did (from its outcome trees, `manifests/*.json.gz`)

`tools/d3/collect_xfam.py` (`check_eth_wallet`) fails the run unless these facts hold. All 8 runs
pass.

On every run: the global deployment succeeds; direct `get_nonce` calls return a value; the

the wallet; the ETH-implicit control with local code returns a value; the one without code fails
with `CodeDoesNotExist`; the named account holding magic bytes fails with
`PrepareError(Deserialization)`. Each of the four magic variants therefore ran the global wallet's
code, and none ran its own magic bytes.

### A nearcore finding (predeploy)

A call on a magic-hash wallet before the global wallet exists fails with `CodeDoesNotExist` on the
chunk producer. **nearcore's own stateless validator rejects that chunk**: `validate:
StorageError(MissingTrieValue { context: TrieMemoryPartialStorage, hash: FAq9t… })`, where
`FAq9t…` is the localnet wallet's code hash. The producer's `ContractStorage::get` misses the code and
returns `None` (`core/store/src/contract.rs`). The validator's partial storage instead records the
miss and fails the witness. In the test environment the wallets' shard then stalls, because its
chunks get no endorsements. This is why the default table deploys first and the predeploy cases
are a separate short run. Population: 54 honest chunks (22 rejected by cold nearcore) and 912
mutants.

Lean rejects all 22 with `invalid: MissingTrieValue (contract code)`: the redirect resolves to the
global hash, and the witness has no code for it. The control below accepts all 22.

## Results

Population: 931 honest chunks + 9,719 mutants = **10,650 cases**. `tools/d3/replay_successor.py`
(the integrated harness, which also compares domain labels) and
`tools/d3/summarize_eth_wallet.py` (verdict against nearcore's `expected_rel`) produced these rows.
A *wallet case* is a chunk whose main transition ran code on one of the magic-hash accounts, or a
mutant of one.

|---|---|---|---|---|---|
| `allFeatures`, all cases | 2,816 | 7,827 | 0 | **0** | 6 / 1 |
| `allFeatures`, wallet cases | 587 | 1,714 | 0 | **0** | 3 / 1 |
| `signed`, all cases | 1,721 | 5,971 | 0 | **0** | 1,862 / 1,096 |
| `signed`, wallet cases | 0 | 711 | 0 | **0** | 1,006 / 588 |
| control, all cases | 2,229 | 7,805 | 587 | **22** | 6 / 1 |
| control, wallet cases | 0 | 1,692 | 587 | **22** | 3 / 1 |

Per run (`allFeatures`, accept/ok + reject/err): ew701 642 + 1,744 (4 OOD), ew702 669 + 1,810,
ew703 679 + 1,816 (3 OOD), ew704 617 + 1,700, ewp791 44 + 141, ewp792 55 + 201, ewp793 66 + 260,
ewp794 44 + 155.

* **The 7 `allFeatures` exclusions** are code-blob mutants (`code.drop`/`flip`/`none`/`truncate`)
  of two chunks in which baseline traffic deploys and calls a contract. Lean reports the named
  W08 race exclusion `out of domain (e.code_prep_race)`, never an accept. The code hashes involved
  are baseline contracts, not the wallet. Six of the seven are nearcore rejects. The integrated
  harness counts 2 of them as `domain_exclusion_where_in_domain`, because the generator labels
  these xfam mutants without the race label. This is the same pattern as the 9 rows in
  `cross-family-fixtures` "Non-matching rows". Every other row partitions as
  `verdict_compared_agree` (8,458) or `verdict_agree_outside_domain` (2,185; the old D3α
  classifier labels wallet calls `e.eth_implicit_local`).
* **Signed tier.** The harness passes with 0 disagreements: 6,284 compared rows agree, 1,408 agree
  outside the domain, and 2,958 are asserted exclusions. The signed tier never decides a wallet call. All 166 honest
  wallet chunks are out of domain with `out of domain (e.wasm-α): ETH-implicit account with a local
  contract (legacy wallet resolution)` (1,511 rows in total). The 711 wallet-case rows it rejects
  are mutants rejected before execution (header, proof and fact mutants), all nearcore rejects. So it
  excludes the branch and decides it nowhere, consistent with `allFeatures`.
* **Blind** (`tools/mainnet-replay/blind_corpus.py`, `allFeatures`): all 931 honest chunks were
  run. 908/908 gradable chunks match every produced output: state root, outcome root, gas, balance
  burnt, outgoing receipts root, proposals, tx root, encoding and congestion. 22 are nearcore
  rejects (not gradable) and 1 is a genesis-main claim. Every blinded control rejected
  (`replay/blind/report.json`).

### Deliberate-breakage control

`control/ablate-eth-redirect.patch` makes `resolveCode` treat an ETH-implicit account with a magic
hash as having no contract. The patch was applied to the tree, the checker
(`checker_control_sha256` in `generation.json`) was built from it, and the patch was then reverted.
The default checker is unchanged. A runtime flag was not used, because `resolveCode` is unfolded by
proofs (`TierFlagsEq.Sim.resolveCode`, `TierO3Rec`, `TierO4NSSim`, `TierWhole`), and a new branch
there would move them.

The control changes **609** rows, all of them wallet cases:

* 587 nearcore-valid wallet chunks and mutants that `allFeatures` accepts are rejected:
  586 for `main transition post state root` and 1 for `InvalidOutcomesProof`. Every honest wallet
  chunk of the default runs flips (144/144).
* 22 predeploy chunks that nearcore rejects are **accepted**. Without the redirect there is no
  code to miss, so the control computes `CodeDoesNotExist` like the producer did. This is the
  soundness side of the redirect: the family detects its removal as an accept of a nearcore
  reject.

## Committed files

* `cases.tar.gz` and `cases-index.json`: 14 cases. These are 8 honest wallet chunks in which
  `rlp_execute` returned a promise (2 per default run), 2 of their mutants, and the first
  nearcore-rejected predeploy chunk of each predeploy run. For each case the index records its
  origin, input hashes, nearcore verdict, and the `allFeatures` and control verdicts: 14/14
  `allFeatures` agree, and the control is wrong on all 12 honest ones.
* `manifests/<run>.json.gz`: the collector's manifest, with every scenario step, nearcore's
  outcome tree and the family facts.
* `replay/{allFeatures,signed,control}/`: the integrated harness report and per-case rows (gzip),
  `replay/blind/report.json`, and `replay/summary.json` (the tables above).
* `generation.json`: commands, seeds, binary and source hashes, and the baseline identity check.
* `control/ablate-eth-redirect.patch`.

## Reproduce

```
bash oracle/scripts/link-nearcore.sh
CARGO_TARGET_DIR=$T cargo build --release --manifest-path oracle/v3-successor/Cargo.toml; B=$T/release/near-arena-oracle-v3-successor
NEAR_SUCCESSOR_SCENARIO=eth-wallet NEAR_XFAM_MUTATE_EVERY=4 $B gen --domain d3 --seed 701 --first-chain 0 --chains 1 \
  --blocks 110 --mutate-every 0 --code-mutant-p 0 --ood-cap 100000 --drop-cap 12 --min-gas-price 100000000 --out ew701
NEAR_SUCCESSOR_SCENARIO=eth-wallet NEAR_XFAM_VARIANT=eth-wallet-predeploy NEAR_XFAM_MUTATE_EVERY=2 $B gen --domain d3 \
  --seed 791 --first-chain 0 --chains 1 --blocks 12 --mutate-every 0 --code-mutant-p 0 --ood-cap 100000 --drop-cap 12 \
  --min-gas-price 100000000 --out ewp791
python3 tools/d3/collect_xfam.py --source ew701 --out col/ew701     # fails on a violated family fact
cat col/*/honest.txt col/*/mutants.txt > all.txt
python3 tools/d3/replay_successor.py --tier allFeatures --cases-file all.txt --out rep/allFeatures --jobs 5   # also --tier signed
git apply docs/evidence/lean-chunk-completion/eth-wallet-fixtures/control/ablate-eth-redirect.patch  # control build, then revert
python3 tools/mainnet-replay/blind_corpus.py --binary CHECKER --cases col-honest.txt --root / --out rep/blind
python3 tools/d3/summarize_eth_wallet.py --tier allFeatures=rep/allFeatures/results.jsonl \
  --tier signed=rep/signed/results.jsonl --control ablated=rep/control/results.jsonl:allFeatures --out summary.json
```

All other runs are listed in `generation.json`. The generator without a scenario is
**byte-identical** to the unmodified sources (`0e7a77fd4`): seed 7, 2 chains, 40 blocks,
`--mutate-every 10`, 8,545 files, `diff -r` empty. The scenario changes generation only. `make
pin-check` passes (no signed source changed).
