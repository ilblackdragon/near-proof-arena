# D1 ⊄ D2: a genesis `epoch_start_after` flag the lower rungs never check

Found 2026-10-30 while scoping the D1 ⊂ D2 simulation for `WitnessLift` (workplan item 11).

## The difference

* `checkD0` / `checkD1` require every `epoch_start_after` flag to be 0
  (`out of domain (c.single_epoch): epoch start`) and never compare the flags with the block
  headers.
* `checkD2` / `checkD3` compare them (`ChunkValidationD2.lean`, "epoch_start_after vs headers"):
  for every block of the segment `!b.isGenesis || flag = 1`.

A segment whose oldest block (the stop block `B1`) is the genesis block has the honest flag 1 there,
so D0/D1 exclude the honest claim. With the flag set to 0 — a false trusted fact — D0/D1 accept and
D2/D3 reject `invalid: epoch_start_after inconsistent with the headers`.

## Cases

`cases/*`: six d1run `ood/*` cases (honest chains, nearcore cold `ok` on the witness) whose claim's
flags were zeroed by `esa_zero.py` (copies the witness unchanged, rewrites only the
`epoch_start_after` bytes of `claim.bin`).

| case | flags before | D0 | D1 | D2 | D3 (`--tier signed`) |
|---|---|---|---|---|---|
| `00-h10003-s2` | `[0,0,1]` | ood (`w.no_txs`) | accept | reject | reject |
| `00-h10004-s1` | `[0,0,0,1]` | ood (`w.no_txs`) | accept | reject | reject |
| `01-h10003-s3` | `[0,0,1]` | ood (`w.no_txs`) | accept | reject | reject |
| `02-h10003-s1` | `[0,0,1]` | accept | accept | reject | reject |
| `03-h10003-s0` | `[0,0,1]` | accept | accept | reject | reject |
| `03-h10004-s1` | `[0,0,0,1]` | accept | accept | reject | reject |

Every reject reason is `invalid: epoch_start_after inconsistent with the headers`. The original
(unmutated) cases are all D1 `out of domain (c.single_epoch): epoch start`.

## What it means

* **Not a nearcore soundness bug.** The witness is the honest, nearcore-valid one; nearcore never
  reads `epoch_start_after`. What D0/D1 accept is a claim carrying a false trusted fact
  (claim-v3 §2.2, the flags are trusted inputs; UQ-013 is their binding).
* **The rung inclusions are false as stated**: `D1 ⊂ D2`, `D1a ⊂ D3`, `D0 ⊂ D3`. So
  `relD1a_relD3_of_d1_d2` (D2SubD3.lean) has a false hypothesis, and `WitnessLift` with the identity
  witness fails on this pair. With any other witness it fails too, because the D2/D3 rejection reads
  only the claim (argued from the pipeline order; not proved as a theorem).
* **Two ways to close `WitnessLift`** (a decision for the owner, since D0/D1 are rungs of the signed
  `near-chunk-v3` union statement):
  1. add D2's genesis rule to D0/D1 (`check (blks.all (!·.isGenesis))` under their all-zero flags,
     as `invalid: epoch_start_after inconsistent with the headers`) — a strictly stronger claim
     discipline, which moves exactly these false-fact claims from accept to reject; or
  2. keep D0/D1 and state the inclusion and the lift under the claim condition
     "no genesis block in the segment" (decidable from the claim alone).
