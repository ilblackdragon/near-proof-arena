# Independent global-action/cache fixtures

Pinned nearcore: `44f7ae6cd7ef08bab604e20a473bf77e35d4c993`, PV86. Generated by the separate
`oracle/v3-successor` crate; no signed oracle source was changed.

Two final-source 140-block windows (seeds 2718 and 31415) produced 978 honest chunks, all accepted
by the cold native validator, and 1,166 mutants. Manifests select 99 relevant honest cases and
166 mutants. Their files, binary and collector are hashed. `cases/` retains 28 small honest chunks
covering actual global action outcomes, distribution delivery and deployment/cache sequences.
Integrated replay is archived under `replay/{globalActions,completeCodeGlobal}/`: both tiers pass
265 cases, with 162 accepts, 99 rejects and four asserted unrelated key/crypto exclusions. Honest
cases split into 95 accepts/four exclusions; all 166 mutant verdicts agree. The committed 28-case
selection includes 26 accepts and two key exclusions, checked explicitly in CI. Generic `w.shape`
metadata is not waived wholesale: successful new global executions compare the raw oracle verdict,
while unsupported key shapes retain their precise guards. Generation alone is not Lean validation.

Observed in each window: three successful global deployments (including redeployment nonce),
hash/account use+call success, missing-use action failure, use+call rollback, two successful
third-party/repeated state initializations, missing-code initialization failure and insufficient
storage-deposit failure. Each window records 12 incoming global-distribution receipts. The endorsed
chunk headers bind roots, outcomes, gas, receipts, balances and congestion; accepting those complete
fixtures checks that binding. Transaction-stage labels and executed results remain separate in the
manifest to prevent labeling a submitted transaction as an executed success.

`cache-incomplete-*.json` retains raw cold-validator cache-dependent mutant observations, including
both accepts and rejects. They are **not** complete-code witness-policy expectations. The baseline
classifier does not fully trace global-identifier cache dependencies, so absence of `e.code_cache`
is not evidence of cache independence for global calls.

Reproduction: build `oracle/v3-successor` with Rust 1.93.0 against the pinned checkout, then follow
its README's global-cache commands. Seed2718 uses default `--max-d3 4`; seed31415 uses `--max-d3 8`.
Both use `--code-mutant-p 0.2 --mutate-every 0 --ood-cap 2000`, with no contract override. Source
hashes and executable hash are in `generation.json`. Selected paths refer to local raw runs;
committed `cases/index.json` records their origins. The two run outputs were independently judged,
not synthesized by mutating Lean's answers.

`codec-vectors.json` contains 12 direct pinned-nearcore Borsh probes: reversed maps and duplicate
keys for StateInit, Action, SignedTransaction and SignedDelegateAction, plus four malformed inputs.
Canonical bytes are independently checked against Python layouts. Transaction hashes are checked
against the canonical unsigned transaction; delegate hashes and deterministic IDs are taken directly
from nearcore and checked stable after canonical re-decoding. This does not claim signature validity.
