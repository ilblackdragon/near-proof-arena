# Yield/resume whole-chunk fixtures (W07)

Validator-produced chunks from the pinned nearcore `44f7ae6cd7ef08bab604e20a473bf77e35d4c993` (PV86),
generated by `oracle/v3-successor` with `NEAR_SUCCESSOR_SCENARIO=yield`. No signed source changed.
Before this, no corpus case contained a scenario-driven yield. Hashes are in `generation.json`.

## Reproduce

```
bash oracle/scripts/link-nearcore.sh
CARGO_TARGET_DIR=/tmp/lean-global-oracle-target cargo build --release --manifest-path oracle/v3-successor/Cargo.toml
B=/tmp/lean-global-oracle-target/release/near-arena-oracle-v3-successor
NEAR_SUCCESSOR_SCENARIO=yield $B gen --domain d3 --seed 4242 --chains 1 --blocks 250 --p-missing 0 \
  --mutate-every 0 --code-mutant-p 0 --ood-cap 100000 --out y4242
NEAR_SUCCESSOR_SCENARIO=yield $B gen --domain d3 --seed 1729 --first-chain 1 --chains 1 --blocks 250 \
  --mutate-every 0 --code-mutant-p 0 --ood-cap 100000 --out y1729
python3 tools/d3/collect_successor_scenarios.py --source y4242 --out manifest-y4242.json   # also y1729
python3 tools/d3/select_successor_fixtures.py --manifest manifest-y4242.json --manifest manifest-y1729.json \
  --out cases --mutants-per-case 2
```

Lean: `cd spec/lean/v3 && lake build nearspec-v3-check-successor`, then
`python3 tools/d3/replay_successor.py --tier allFeatures --cases-file LIST --out OUT --jobs 8` (also
`--tier storageResolution`), and blind
`python3 tools/mainnet-replay/blind_corpus.py --binary BIN --cases HONEST_LIST --root cases --out OUT`.

y4242: chain 0, 4 shards, no missing chunks; 970 honest chunks (970 accepted by the cold
validator), 3,544 mutants. y1729: chain 1, 5 shards, 10% missing chunks; 1,074 honest, 3,246 mutants.
Baseline D2/D3 traffic runs alongside. Every chunk that ran the yield contract has the full mutant set
(headers, trusted facts, transaction validity, every dropped witness node, code blobs).

## Coverage (nearcore outcomes, y4242)

`tools/d3/collect_successor_scenarios.py` checks every row against nearcore's recorded outcome tree,
not against labels or Lean (`manifest-*.json`). `ret` is the yield-account receipt's return; `cb` is the
callback's return, `[PromiseResult status] ++ payload` (01 = resumed, 02 = timeout); heights are
execution heights. All 36 expectations hold in both runs. In y1729, missing chunks shift two timing
alignments: race/cancel are in different chunks. They are recorded as `timing_deviations`.

| Step | nearcore result |
|---|---|
| create, resume in a later chunk (00, 05) | create returns data id (h 10008); resume returns 01 (h 10009); callback `01 later-chunk` (h 10010) |
| create + resume in one receipt (02) | returns 01; callback next chunk |
| create and resume in one chunk, two transactions (03, 04) | both at h 10008; resume 01; callback h 10009 |
| timeout (01, 15, 31) | callback `02` exactly 201 blocks after creation (timeout loop at +200). 15 is the yield whose 1,025-byte resume failed |
| resume twice in one receipt (06, 07) | `0101`; one callback |
| two resumes, same chunk (08–10) | both return 01; one callback with the first payload, the second PromiseResume is ignored |
| resume after completion (11), after timeout (33) | 00 |
| wrong data id (12) | 00; malformed 31-byte id (13): failure `yield resumption token is malformed` |
| payload 1,024 B (14, 16) | 01, callback receives 1,024 bytes; 1,025 B (17): failure `exceeds the 1024 byte limit`, rollback, the yield later times out |
| cross-shard trigger (18, 20) | shard-1 account calls create/resume on shard 3; callback emits a receipt executed on shard 0 (h 10030) |
| cross-shard trigger + timeout (19) | timeout callback still emits the cross-shard receipt |
| create then panic (21) | failure; no yield, no callback ever |
| `promise_yield_create_with_id` (22–25, 31) | index 0; duplicate id in the same chunk returns u64::MAX; resume by id 01; unknown id 00 |
| returned yield (26, 27) | the receipt returns `SuccessReceiptId(yield)`; resolved by the callback |
| callback panics (28, 29) | resume 01; callback failure |
| resume in the timeout chunk (30, 32) | resume at h 10235 = creation + 200; the timeout loop of that chunk also emits a timeout resume; callback gets `race` |
| resume one chunk after the timeout fired (34, 35) | local resume before the incoming timeout resume: nearcore cancels it (`ResumeInitiated`); callback gets `cancel` at +202 |

PromiseYield receipts are instant (`Receipt::is_instant_receipt`) and PromiseResume receipts are addressed
to the yielding account (`ext.rs` `create_promise_resume_receipt`; timeouts in `lib.rs:3036-3045`). The
pinned protocol therefore cannot route either receipt type across shards outside resharding. These
fixtures cover the cross-shard parts that exist: cross-shard triggering transactions and receipts,
and cross-shard receipts emitted by resumed and timed-out callbacks. PromiseResume receipts do cross
chunks: outgoing to self, incoming in the next chunk.

## Lean results

Checker `a603a893…` built from `257ad1c52` (`generation.json`). **No disagreement; no Lean change was
needed.**

* Full runs, verdict replay (`replay/full-run-verdicts.json`, per-case rows gzipped):
  * `allFeatures`: 8,834 cases (2,872 accepts, 5,962 rejects), all agree with nearcore. 98 are baseline
    cases outside the declared domain (ML-DSA, ecrecover/global/gas-key hosts); their verdicts also agree.
  * `storageResolution`: the same 8,834 cases. 95 baseline cases are asserted exclusions
    (out_of_domain with the matching label). There are 0 disagreements. No yield case is out of domain
    on either tier.
* Committed cases (`cases/`, 74 honest + 128 mutants, `replay/fixtures/`): 202/202 agree on both tiers
  (74 accepts, 128 rejects). Blind 74/74 match.
* Blind replay of all 2,044 honest chunks of both runs (`replay/full-run-blind*.json*`): 2,011 match,
  0 mismatches, 33 harness `blind_error`s on baseline chunks. 8 are first-chunk claims whose
  `post_state_root` cannot be blinded. 25 are ML-DSA/UseGlobalContract shapes `blind_inputs` refuses.
  None contains a scenario step.

## Not covered

* PromiseYield/PromiseResume receipts crossing shards: protocol-impossible without resharding, as above.
  Resharding composition belongs to W11.
* A timeout deferred by the chunk *compute* limit. Deferral by the storage-proof soft limit is in
  `../storage-limit-fixtures/`.
* Yield receipts in the delayed queue or outgoing buffers under congestion.
