# Experimental LaBinius export: actual bytes, decoding still open

2026-10-24. Both real hash-batch proofs export to **165,950 bytes**, including
64 public-root bytes and all seven framed sections below. Independent structural
parsing consumes every byte; truncation, trailing data and oversized section
lengths reject. This is NOT yet a cryptographically verified wire proof: the
native proof is verified before export, but no native decoder exists yet.

The earlier ~116 KB was an analytical estimate. In particular,
`print_witness_pp` estimates coefficient entropy with a Gaussian approximation
and includes a `FIXME: not necessarily gaussian`. This export instead stores
the terminal witness's 542 polynomials as 69,376 bytes of fixed signed-16-bit
coefficients. Even that conservative encoding leaves 134,050 bytes below the
300,000-byte target FOR THIS COMPONENT. It says nothing yet about the combined
receipt/VM/history proof size.

## Format and provenance

`NPTMPL01` followed by seven `(u64_le length, bytes)` sections in table order.
The inner `NPLAB001` payload stores ring degree/modulus width, commitment
dimensions and packed values; every proof level's dimensions, decomposition
parameters, JL nonce/projection, norm and packed u1/u2/lift polynomials; then
terminal witness ranks, norms and coefficients. No pointers, native `size_t`
images, padding bytes or cached analytical sizes are copied.

The Dachshund `alpha` array is deliberately omitted: `reduce_simple_commit`
recomputes it from the statement and commitment using the transcript. The public
commitment key is regenerated by the existing setup code. The outer RNS images
are still implementation-specific: their exact bytes enter the existing
transcript, so converting them to canonical coefficients requires an exact
reconstruction argument or a versioned transcript change. This is not a portable
canonical-format claim.

The packet assumes externally pinned algorithm, capacity policy, parameters and
setup seed. They must be bound to a trusted verifier identity; this export is not
a self-describing production protocol. The public root is not bound to the NEAR
receipt relation yet.

Source/logs/patches are in `evidence/export-codec/`. Independent reader and
malformed-framing checks: `audit_export.py`; packet SHA-256 and structural counts:
`evidence/export-audit.json`. Actual packets stay in scratch at the paths in that
audit. Rebuild using the earlier private-session patch plus these changes.

Proving and in-memory verification passed for both exported proofs, with 12
negative checks. Logged 1.67/1.71 s readiness excludes export (which currently
runs after honest verification), native input export and cold circuit/setup.
Measure the serialization-inclusive critical path once decoding is implemented.

## Next gate: decode and independently verify

Build a bounded native decoder and test fresh-process verification against an
independently supplied expected root and pinned circuit/setup. Do not expose the
C verifier as an untrusted parser merely by reconstructing its pointers.

Required checks include lengths/ranks, supported decomposition parameters,
shift/division bounds, allocation/product bounds, terminal witness dimensions,
canonical coefficients and full consumption. Validate cross-level relationships:
the C verifier derives allocations from sums/products of proof metadata. The
structural Python reader deliberately does not certify those algebraic or memory
safety conditions. Re-encode decoded honest proofs and require byte equality;
mutate every section, not just the transcript and root. Only after this gate can
the 165,950 bytes be called a verified serialized component proof.

Receipt/hash binding, full NEAR semantics, recursive history, concrete PQ security
and representative p95 latency remain additional completion requirements.
